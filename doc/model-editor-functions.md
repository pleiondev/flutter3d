# Функциональность редактора 3D-моделей — обзор

Источники: `doc/model-editor-plan.md` (317+ пунктов плана, актуальная версия от
2026-09-09/10/11) и `doc/plan-status.json` (фактический статус каждого пункта
на 2026-09-11). Документ пересказывает план человеческим языком по
функциональным областям, а не по порядку пунктов, чтобы дизайн можно было
скорректировать, глядя на возможности, а не на таблицу. В скобках — id пункта
плана, для трассируемости. Внутри раздела: ✅ Готово, ⚠️ Частично (с причиной
в одну фразу), ⬜ Не начато. Статус «частично» всегда означает, что базовый
сценарий работает, а ограничение — сознательное и записанное, не забытое.

## Ядро меша (half-edge структура и операции редактирования)

Редактируемая геометрия: половинно-рёберный меш на типизированных массивах,
персистентная история, выделение, базовые и продвинутые операции.

**✅ Готово**
- Half-edge структура `EditMesh` с надгробиями, `compact()`, Эйлеровыми
  примитивами, `validate()` (mesh-11)
- Персистентная история через журнал прежних значений вместо копирования
  целиком (mesh-10)
- Слои атрибутов: позиции/скининг по вершине, UV/цвет по углу,
  sharp/seam/crease по ребру, материал/сглаживание по грани (mesh-12)
- Импорт готового меша со сваркой швов, ремонтом ориентации, расщеплением
  неманифолдных рёбер (mesh-13)
- Построение GPU-совместимого макета (триангуляция, нормали, дедуп вершин)
  (mesh-14)
- Триангуляция n-гонов (mesh-15), нормали и их пересчёт (mesh-16), тангенсы
  (mesh-17)
- Бинарная сериализация меша (mesh-18)
- Выделение: уровни (вершина/ребро/грань), loop/ring, рост/сжатие, по
  материалу (mesh-19)
- BVH по треугольникам для пикинга (mesh-20) и сам пикинг (mesh-21)
- Перемещение/поворот/масштаб выделения с точкой опоры (mesh-22)
- Экструзия граней и рёбер (mesh-23), разрез петли (loop cut, mesh-24)
- Сварка по расстоянию, растворение рёбер/вершин (mesh-25)
- Удаление, разделение на объекты, дублирование (mesh-26)
- Диагностика меша: n-гоны, неманифолдность, вырожденные грани, эйлерова
  характеристика (mesh-27)
- Параметрические примитивы (куб/плоскость/цилиндр/сфера/тор/лофт) с
  квадовой топологией, готовой для редактирования (mesh-28, mesh-29)
- Меш пригоден для выполнения в отдельном изоляте (mesh-30)
- Замеры производительности и фаззинг (500 случайных операций × 3 сида) на
  устойчивость инвариантов (mesh-31, mesh-32)
- Эталонные кадры базовых операций (экструзия, разрез петли, лофт,
  sharp-vs-smooth) (mesh-33)
- Заполнение отверстий, расщепление неманифолдных рёбер, выворачивание
  оболочек — «починка», а не только диагноз (mesh-81n)

**⬜ Не начато**
- Веса скиннинга как операция на меше — накопление, усечение, перенормировка
  (mesh-60), хранение множества форм-ключей (mesh-61, mesh-62)
- Упрощение геометрии (decimation/QEM) (mesh-70), полноценная UV-развёртка
  с LSCM и упаковкой островов (mesh-71)
- Скульптинг: мультиразрешение над мешем (mesh-72), ремеш (mesh-73)
- Генерация форм столкновения из меша — выпуклая декомпозиция, коробки,
  капсулы (mesh-80n)

## Модификаторы (стек неразрушающих операций)

**✅ Готово**
- Каркас модификаторов: тип, контекст, стек с мемоизацией по кэшу базового
  меша (mesh-40)
- Зеркало со сшивкой шва (mesh-41), массив с детерминированными id (mesh-42)
- Внутренняя фаска / inset с поправкой на угол (mesh-43)
- Подразделение по Catmull-Clark с полу-резкими фасками (Pixar), билинейный
  UV по углам (mesh-45)
- Сглаживание по Лапласу с сохранением объёма (HC-коррекция) (mesh-46)
- Булевы операции (union/subtract/intersect) через BSP-дерево (mesh-47)
- Хранение стека на объекте, кэш по версии геометрии/модификаторов
  (mat-18), команды стека и разбор JSON (mat-19)

**⚠️ Частично**
- Фаска рёбер и вершин (mesh-44) — работает на замкнутой области выделения
  (каждая грань, тронутая фаской, должна быть выделена целиком); один
  плоский срез без сегментов и профиля не реализован
- Булевы операции (mesh-47) — объём и предупреждение о копланарном случае
  верны всегда, но реконструированный меш не гарантированно герметичен
  (T-стыки после разбиения треугольника — известное свойство алгоритма, не
  только этой реализации)

**⬜ Не начато**
- Обёртка булевой операции как модификатор стека с операндом-объектом
  (mesh-48) — ядро (`booleanOp`) готово, обёртки над стеком нет
- Golden-кадры фазы 2 для модификаторов (mesh-49)

## MCP-инструменты для агента

**✅ Готово**
Полный набор инструментов первой версии, зеркалящих команды документа —
объектные, мешевые, материальные (базовые), модификаторные, выделения,
сессионные глаголы (list/select/run/undo/redo/check/save/export/import/
journal). Каждая новая команда автоматически требует своего инструмента —
это проверяется тестом, поэтому расхождений между командами и инструментами
не бывает.

**⬜ Не начато — целый функциональный трек («агент, который видит модель»)**
Сегодня агент правит модель вслепую: он получает числа проверки готовности,
но не картинку. Требует отдельной подготовки движка (вынести последние
Flutter-зависимости из слоя железа и рендер-ядра в четырёх точках):
- Рендер проекта в PNG без GPU-виджета (mcp-05n) и MCP-инструмент `render`
  с готовыми ракурсами (mcp-06n), контактный лист из нескольких видов
  (mcp-07n), режимы показа — материал/каркас/нормали/выделение (mcp-08n)
- Составные рецепты одной транзакцией: `cleanup()`, `makeGameReady(profile)`,
  `buildFrom(spec)`, `inspect()` (mcp-09n)
- Разделение авторства шагов истории человек/агент, отмена только своих
  шагов (mcp-10n), группировка вызова агента в одну транзакцию (mcp-11n)
- Полный журнал действий агента с воспроизведением (mcp-12n)
- Тот же сеанс редактирования доступен из GUI по локальному HTTP, не только
  по stdio headless-серверу (mcp-13n), синхронизация с открытым окном
  (mcp-14n)
- Импорт/экспорт как глаголы сессии с воротами готовности и `force` (mcp-15n)

Материалы (`listMaterials`, `setMaterialField`, `bakeTextureGraph`, свет)
и анимация (`autoRig`, `paintWeights`, `bakeIk`) как MCP-инструменты — тоже
не начаты (mat-32, anim-30), поскольку сами материальные/анимационные
функции фазы 2–3 ещё не сделаны за пределами базового набора.

## Материалы и текстуры

**✅ Готово**
- Материал как часть документа проекта: слоты на объекте, команды
  добавления/удаления/назначения/дублирования материала, назначение
  текстуры и загрузка изображения (mat-01)
- Чтение размеров и формата текстуры из заголовка файла без декодера, с
  пересчётом веса под целевой формат сжатия и с бюджетом по трём профилям
  (десктоп/мобильный/веб) (mat-02 частично — см. ниже, mat-28)
- Правила проверки готовности к экспорту (часть mat-22): материал в режиме
  прозрачности без реальной альфы, текстура на неподдерживаемом UV-канале —
  обе новые правки поверх уже готовых проверок n-гонов после булевой
  операции и неманифолдности после зеркала (эти два были готовы раньше как
  часть базовых проверок mesh/geometry)

**⚠️ Частично**
- `TextureInfo` из заголовков файлов (mat-02) — сделано для PNG/JPEG и для
  распознаваемых форматов сжатия KTX2 (BC1/BC3/BC7/ETC2/ASTC 4×4); формат
  KTX2, который энкодер движка ещё не пишет (Basis Universal и т.п.), даёт
  честный вес по данным файла, а не расчётный
- Правила готовности к экспорту (mat-22) — из семи названных в плане правил
  сделаны два новых (blend без альфы, текстурный UV-канал ≠0); два уже были
  готовы до этого пункта, одно ссылается на несуществующее поле формата,
  одно ждёт бюджета текстур как отдельного модуля (который, в свою очередь,
  сделан — mat-28), одно вынесено на уровень приложения

**⬜ Не начато**
- Полная панель «Материал» со всеми свойствами и настройками освещения
  (mat-04, урезанная версия для фазы 1 — mat-04a-n — тоже не начата)
- Перенос общего кода панели материала в отдельный пакет для двух
  редакторов (mat-03), слоты текстур с превью (mat-05), поле цвета с
  HSV/hex (mat-06), кэш скомпилированных материалов (mat-07)
- Внешний `.fmat`-файл материала (mat-08)
- Декодер изображений на чистом Dart для графа текстур — PNG inflate,
  baseline JPEG (mat-09n)
- Компоновщик текстур: фиксированный граф нод (Image/Color/Blend/Levels/…),
  запекание на CPU, панель редактирования графа (mat-10, mat-11, mat-12,
  mat-13)
- Студия материалов — отдельная сцена предпросмотра (mat-15), HDRI-окружение
  из LDR-панорамы (mat-16), из `.hdr` (mat-17)
- Панель стека модификаторов в интерфейсе (mat-20)
- Свет и окружение как часть проекта: источники, тени, экспозиция, команды
  управления (mat-23), режим «Сцена» с расстановкой ассетов (mat-24),
  визуальные гизмо источников света (mat-25)
- Подгонка текстур под бюджет — уменьшение размера, приведение к степени
  двойки (mat-29)
- Офлайн-энкодер текстур в сжатые форматы (mat-30)
- Эталонные кадры материалов/модификаторов/сцены (mat-31)

## Что дальше

**Крупные нерешённые блоки целиком:**
1. **Фаза 3 — конвейер персонажа** (риггинг, скиннинг, IK, ретаргетинг,
   морф-драйверы, таймлайн анимации) — готов только замер FK. Это
   единственный раздел плана, где ничего функционального не начато.
2. **Фаза 4 — профессиональные режимы** (скульптинг, ретопология, UV,
   симуляции ткани, офлайн-рендер, покраска текстур, LOD) — не начато
   вообще; сама фаза помечена в плане как «самая неточная», размеры L
   внутри неё могут удвоиться при реализации.
3. **Трек «агент, который видит модель» (mcp-*)** — сегодня агент работает
   вслепую: MCP-инструменты дают числа готовности, но не картинку. Нужна
   отдельная подготовка движка (`GraphicsDevice.present()` перестаёт
   называть Flutter, рендер-ядро становится плоским пакетом) прежде, чем
   можно добавить инструмент `render`.
4. **Трек игровой графики (gfx-*)** — правки движка параллельно редактору
   (профайлер кадра, отбор источников света без «перескока», контактные
   тени, FXAA); не начато, идёт по своим фазам Г1–Г3, а не по фазам
   редактора.
5. **Оставшиеся два пункта фазы 2**: обёртка булевой операции как
   модификатор стека (mesh-48) и golden-кадры фазы 2 (mesh-49) — ядро
   готово, тонкая обёртка и кадры нет.
6. **Материалы и модификаторы фазы 2 за пределами базового набора**:
   полная панель материала, компоновщик текстур (граф нод), студия
   материалов, режим «Сцена» со светом, стек модификаторов в интерфейсе —
   ядро (`mat-18`, `mat-19`, `mat-28`) готово, весь пользовательский слой
   и текстурный граф не начаты.
7. **Форматы**: собственный читатель FBX (два пункта L-размера), офлайн-
   энкодер текстур в сжатые форматы, USDZ, свет/камеры в словаре формата —
   ни один не начат.
