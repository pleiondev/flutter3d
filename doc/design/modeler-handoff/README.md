# Передача в разработку: 3D-редактор на Flutter

## О чём это

Кроссплатформенный редактор 3D-фигур: импорт распространённых форматов, создание примитивов
и тел вращения, правка меша, материалы, UV, анимация, скульптинг, симуляции, рендер и
конвейер игрового персонажа. Ядро рендера — собственная библиотека **flutter3d**. Целевые
платформы: веб, десктоп, планшет с пером, телефон. Интерфейс — **Material 3** в
минималистичной трактовке.

## О файлах в этом архиве

Файлы в `designs/` — это **дизайн-референсы, сделанные в HTML**. Это не production-код и не
исходники приложения: они показывают предполагаемый вид, плотность и поведение интерфейса.

Задача разработчика — **воспроизвести эти макеты во Flutter** средствами Material 3
(`ThemeData.useMaterial3`, `ColorScheme.fromSeed`, компоненты `NavigationRail`,
`SegmentedButton`, `Slider`, `BottomSheet`, `FilledButton`), а не переносить HTML.
Все размеры и цвета ниже даны в логических пикселях Flutter (1 CSS px = 1 lp).

Открыть макеты: `designs/Экраны редактора.dc.html` в браузере. Второй файл —
`designs/План разработки 3D-редактора.dc.html` — план разработки, фазы, риски, архитектура.

## Точность

**Высокая (hi-fi).** Цвета, размеры, плотность и состав панелей окончательные и подлежат
точному воспроизведению. Исключение — содержимое вьюпорта (модели, скелеты, ткань): это
схематические заглушки, реальную геометрию рисует flutter3d.

Оформление страницы вокруг макетов (серифный шрифт, светлый фон, подписи) — это оболочка
документа, а **не** часть продукта. К приложению относится только тёмный интерфейс внутри
скруглённых прямоугольников.

## Тема Material 3

Тёмная схема. Один акцент на весь редактор.

| Роль | Hex | Где |
| --- | --- | --- |
| `surfaceContainerLowest` | `#0B0E0F` | фон окна |
| `surface` (вьюпорт, тёмная часть) | `#0E1112` | подложка сцены |
| `surfaceContainerLow` | `#131617` | панель инструментов слева, строка статуса |
| `surfaceContainer` | `#171A1B` | верхняя панель, панель свойств, лист |
| `surfaceContainerHigh` | `#1B1F20` | поля ввода, ноды, чипы, плавающие панели |
| `surfaceContainerHighest` | `#262A2B` | выделенная строка списка |
| `onSurface` | `#E1E3E3` | основной текст |
| `onSurfaceVariant` | `#BFC8CA` | второстепенный текст, неактивные иконки |
| `outline` | `#899295` | подписи, служебные значения |
| `outlineVariant` | `#3F484A` | разделители, дорожки ползунков |
| `primary` | `#5FD4E4` | заливка ползунков, выделение в 3D, активные иконки |
| `primaryContainer` | `#004F58` | фон активного сегмента, основная кнопка |
| `onPrimaryContainer` | `#A2EEFF` | текст и иконки на `primaryContainer` |

| `error` / предупреждение | `#FFB86B` (текст `#FFD9B0`, фон `#3A2118`) | предупреждения бюджета |

Вьюпорт: радиальный градиент `radial-gradient(120% 100% at 50% 0%, #1A1E1F 0%, #0E1112 70%)`.
Сетка пола: линии `#2A3234` шагом 48 lp, положены в перспективе (наклон ~66°), прозрачность 0,35–0,55.

## Каркас приложения

Один каркас на все режимы. Меняется только содержимое.

```
┌─ верхняя панель 52 ──────────────────────────────────────────┐
│ имя файла        [переключатель режимов]      undo redo Экспорт │
├────┬──────────────────────────────────────────┬──────────────┤
│ 52 │  вьюпорт (+ нижняя область режима)       │  свойства    │
│рел.│                                          │  250–330     │
├────┴──────────────────────────────────────────┴──────────────┤
│ строка статуса 30: слева метрики, справа готовность          │
└──────────────────────────────────────────────────────────────┘
```

**Правила каркаса**

1. Переключатель режимов — единственный постоянный элемент верхней панели: `Объект`,
   `Меш`, `Материал`, `Анимация`, `Сцена`. Реализовать как `SegmentedButton`.
2. Второй сегментированный переключатель справа от первого — подрежим текущего режима
   (уровень выделения; `Правка / UV / Ретопология`; `Поза / Веса / Ретаргет / Морфы`).
3. Панели не накапливаются: при смене режима содержимое рельсы и правой панели
   заменяется целиком.
4. Строка статуса — постоянная. Слева количественные метрики, справа состояние
   пригодности к экспорту: зелёный `#7EE081` — норма, оранжевый `#FFB86B` — предупреждение.
5. Цвет принадлежит модели. В хроме используется только `primary` для активного состояния
   и `#FF458E` для второго смыслового слоя (швы, playhead, проблемные элементы).

### Адаптация

| Класс ширины | Раскладка |
| --- | --- |
| Десктоп (≥1200) | как на схеме: рельса слева, панель свойств справа |
| Планшет (600–1199) | вьюпорт во весь экран; плавающая палитра слева (кнопки 48); переключатель режимов по центру сверху; свойства — лист снизу высотой ~200 |
| Телефон (<600) | `NavigationBar` снизу (Объект, Меш, Материал, Сцена) вместо переключателя; свойства — компактный лист над навигацией; основное действие — FAB 56 × 56, радиус 18 |

Состав инструментов одинаков на всех размерах.

## Экраны

Нумерация соответствует подписям в макете.

### 01 · Режим «Объект» (фаза 1)
Состояние по умолчанию. Рельса: выделение, перемещение, поворот, масштаб, разделитель,
примитивы, тело вращения, булевы операции. Правая панель, сверху вниз: список объектов
сцены (иконка + имя), трансформация сеткой 3 × 3 (П/В/М × XYZ, числовые поля), стек
модификаторов (строка с именем и переключателем видимости, ссылка «Добавить»).
Вьюпорт: чипы режима отображения слева сверху, круг гизмо ориентации ⌀60 справа сверху,
трёхцветный манипулятор на объекте (X `#FF6B8A`, Y `#7EE081`, Z `#6AA8FF`).
Статус: `Треугольников N · вершин N · материалов N` / `Готово к экспорту в GLB`.

### 02 · Режим «Меш» (фаза 1)
Второй переключатель — уровень выделения: вершины / рёбра / грани (иконки).
Правая панель показывает **параметры последней операции** карточкой на
`surfaceContainerHigh`, радиус 12: заголовок с крестиком, ползунок «Смещение» с числовым
полем, флажки. Ниже — сводка выделения (граней, периметр, площадь).
Ключевое требование: значение операции, выполненной мышью, немедленно доступно для правки
числом. Выделенная грань — заливка `#004F58` 55 %, обводка `primary` 2,5.
Статус справа: `2 n-гона — проверьте перед экспортом` (оранжевый).

### 03 · Планшет (фаза 1)
Плавающая палитра инструментов слева, переключатель режимов по центру сверху, кнопки undo
и экспорт справа сверху (44 × 44, радиус 14), лист снизу высотой 200 с трансформацией в три
колонки.

### 04 · Телефон (фаза 1)
Статус-бар, компактная верхняя строка (назад, имя, меню), FAB, лист 130 над `NavigationBar`
высотой 80.

### 05 · Материал (фаза 2)
Вьюпорт с предпросмотром материала, под ним сворачиваемая панель **графа нод** высотой 250:
ноды 170–210 шириной, радиус 10, шапка ноды `surfaceContainerHighest` (у входной и выходной
— `primaryContainer`), связи — кривые Безье `primary` толщиной 2.
Правая панель: список материалов объекта с цветным кружком, свойства (базовый цвет с
образцом 22 × 22 и hex, ползунки металличности, шероховатости, прозрачности), слоты текстур
(превью 26 × 26, имя, разрешение).
Два уровня доступа: ползунки для простого случая, граф — для сложного, свёрнут по умолчанию.

### 06 · UV-развёртка (фаза 4)
Разделённый вид: слева 3D со швами (`#FF458E`, толщина 3,5), справа квадрат развёртки
400 × 400 на шахматном фоне (клетка 32), острова — полигоны с заливкой 50 % и обводкой 2.
Цвет острова кодирует растяжение: `primary` — норма, `#FF458E` — растяжение.
Правая панель: метод развёртки (два чипа), отступ между островами, флажок автоупаковки,
список островов с коэффициентом растяжения.
Статус: `Заполнение развёртки N % · островов N`.

### 07 · Анимация (фаза 3)
Под вьюпортом таймлайн высотой 270: строка транспорта (44) с кнопкой воспроизведения
⌀36 на `primaryContainer`, номером кадра и переключателем `Ключи / Кривые`; ниже слева
колонка имён костей шириной 180, справа дорожки с ключами — ромбы 12 × 12 (`primary`,
серый `#899295` для неактивных), вертикальная линия текущего кадра `#FF458E` 2 lp с
плашкой номера.
Правая панель: дерево скелета с отступами по уровням, ограничения, список действий.
Статус: `Костей N · действий N · вес влияний 4 на вершину`.

### 08 · Скульптинг (фаза 4)
Единственный режим без боковых панелей: вьюпорт во весь экран, плавающая палитра кистей
слева, карточка параметров справа (радиус 20, ширина 250), переключатель режимов сверху.
Курсор кисти — окружность ⌀140 обводкой `primary` 2 с точкой в центре.
Раскладка одинакова на десктопе и планшете — рассчитана на перо.
Статус: `Треугольников 1 240 000 · плотность 0,8 мм` / `Перед экспортом потребуется ретопология`.

### 09 · Тело вращения (фаза 1)
Модальный экран высотой 720. Слева редактор профиля 520 на сетке 40: ось вращения —
пунктир `#FF458E`, профиль — путь с заливкой `#004F58` 28 % и обводкой `primary` 2,5,
точки ⌀12 (управляющая точка — пустая с обводкой). Внизу три чипа: Точка, Кривая, Ось.
Справа вьюпорт с результатом, обновляемым немедленно.
Правая панель: сегменты, угол, флажки сглаживания и торцов, сводка (вершин, треугольников, высота).
Профиль остаётся редактируемым после создания — фигура хранится параметрически.

### 10 · Ретопология и запекание (фаза 4)
Исходный меш просвечивает под новой сеткой; прозрачность регулируется плавающим ползунком
внизу слева. Новая сетка — кривые `primary` 1,6; активный квад — заливка `#FF458E` 22 %,
обводка 2, углы ⌀9.
Правая панель шириной 290 в двух блоках, разделённых линией: автоматическая ретопология
(целевое число квадов, флажки, кнопка «Пересобрать сетку» на `surfaceContainerHigh`) и
запекание карт (пара источник → приёмник задана автоматически, список карт с флажками и
разрешением, толщина оболочки, основная кнопка «Запечь N карты»).

### 11 · Симуляции и физика (фаза 4)
Физика — свойство объекта. Правая панель: тип (чипы Ткань / Твёрдое тело / Частицы),
параметры материала, взаимодействия (столкновения, ветер, закреплённые вершины), точность.
Под вьюпортом полоса высотой 150: транспорт, кнопка «Запечь симуляцию» и **полоса кэша** —
дорожка 16 lp, радиус 8, просчитанные кадры залиты `#004F58`, текущий кадр — `#FF458E`.
Статус: `Симуляций в сцене N · кэш N МБ` / `Запечь перед экспортом в движок`.

### 12 · Рендер и композитинг (фаза 4)
Слева панель проходов 230 (строки с иконкой видимости) и настройки рендера. По центру
результат рендера в рамке 760 × 428 с плашкой прогресса. Внизу граф композитинга 260,
устройство нод — как на экране 05.
Правка ноды пересчитывает только затронутую ветку; статус показывает время пересчёта.

### 13 · Покраска весов (фаза 3)
Веса окрашивают меш градиентом: 0 → `#2A3A7A`, 0,25 → `#4AA3FF`, 0,5 → `#7EE081`,
0,75 → `#FFB347`, 1 → `#FF3B5C`. Легенда — полоса 140 × 8 в правом верхнем углу.
Под вьюпортом полоса 74: ползунок сгиба выбранной кости (`#FF458E`) для проверки
деформации без выхода из режима, кнопка «Сбросить позу».
Правая панель: параметры кисти (радиус, вес мазка, флажки зеркала и нормализации), влияния
выделенной вершины (имя кости, мини-дорожка, значение), список костей с числом вершин.
Ограничение влияний берётся из профиля проекта, перенормировка — при каждом мазке.

### 14 · Ретаргет и библиотека (фаза 3)
Слева библиотека клипов 230: поле поиска (радиус 18), карточки с иконкой 34 × 34, именем и
длительностью. По центру два вьюпорта рядом: источник (mocap-скелет, серый) и цель
(персонаж с подсвеченным скелетом). Внизу дорожки клипов высотой 22 с ползунком смешивания.
Правая панель: таблица сопоставления костей (`источник → цель`), несопоставленные строки на
фоне `#3A2118` с иконкой и текстом `#FFB86B`; ссылка «Сопоставить автоматически»;
блок корневого движения (`В анимации` / `Кодом`) и коррекции (подгонка под рост, прижим стоп).

### 15 · Морфы и лицевая анимация (фаза 3)
Правая панель 330: список форм, каждая строка — имя (96), ползунок, значение и **точка
ключа** справа (`radio_button_checked` `#FF458E` — ключ есть, `radio_button_unchecked`
`#3F484A` — нет). Ключ ставится прямо в строке, отдельного редактора нет.
Ниже — корректирующие формы, привязанные к углу ведущей кости, и наборы форм чипами.
В вьюпорте точки формы: `primary` — обычные, `#FF458E` — активная.

### 16 · Авториг (фаза 3)
Модальный экран 720. Слева силуэт с восемью опорными точками ⌀16 (пустые, обводка `primary` 3;
активная — сплошная `#FF458E`), между ними пунктирные связи будущих цепочек.
Справа: шаблон (Гуманоид / Четвероногое / Своё), состав (пальцы, позвонки — маленькие
двухпозиционные переключатели; флажки IK и контроллеров), привязка меша (первичные веса,
симметрия), карточка итога: сколько костей будет создано и сколько из них деформирующих.

### 17 · Уровни детализации (фаза 4)
Три вьюпорта рядом с подписями `LOD 0/1/2` и числом треугольников; геометрия визуально
упрощается слева направо. Под ними полоса 96: ползунок расстояния до камеры, дорожка
разделена на три зоны (`#004F58`, `primary`, `#2C3A3D`), метка текущего расстояния `#FF458E`.
Правая панель: карточки уровней (процент упрощения, треугольники, диапазон расстояний),
ссылка «Добавить уровень», флажки упрощения (силуэт, границы развёртки, перенос весов).
Уровни наследуют развёртку и веса.

### 18 · 3D-покраска (фаза 4)
Три области: вьюпорт с курсором кисти (⌀96, обводка `#FF458E`), панель развёртки 300 с
холстом 240 × 240, где мазок отображается одновременно, и правая панель 290.
Правая панель: слои (видимость, имя, режим наложения и непрозрачность), палитра из четырёх
образцов 32 × 32 с обводкой активного (`outline: 2px solid primary; offset: 2px`), радиус и
непрозрачность кисти, маски по кривизне и затенению (берутся из карт экрана 10).

### 19 · Предпросмотр «как в игре» (фаза 3)
Вьюпорт с игровым освещением (градиент `#243440 → #0F181D`). Оверлей метрик слева сверху на
`rgba(11,14,15,0.72)`: кадры в секунду, вызовы отрисовки, треугольники в кадре, кости.
Снизу по центру плавающая панель управления: пауза, сегменты клипов, зацикливание.
Правая панель 330: **бюджеты профиля** — четыре строки с полосой заполнения 5 lp
(зелёная в норме, оранжевая при превышении), карточка предупреждения на `#3A2118`,
условия сцены (освещение, тени рантайма, сжатие текстур, каркас).
Это финальная проверка перед экспортом: рантайм тот же, что в игре.

## Поведение

- **Смена режима** заменяет содержимое рельсы и правой панели целиком; выделение и камера
  сохраняются. Переход без анимации содержимого, только индикатор сегмента (M3, 200 мс,
  `easeInOutCubicEmphasized`).
- **Операция мышью → правка числом.** Любая интерактивная операция (экструзия, скос,
  перемещение) после завершения кладёт карточку параметров в правую панель. Изменение
  значения пересчитывает результат немедленно, без подтверждения.
- **История.** Все правки идут через команды: отмена и повтор, автосохранение. Это же
  основание для будущей совместной работы.
- **Тяжёлые операции** (булевы, ретопология, запекание, симуляция, рендер) выполняются в
  изоляте; интерфейс не блокируется, прогресс показывается на месте кнопки запуска.
- **Проверки экспорта** непрерывны: строка статуса пересчитывается после каждой правки.
  Оранжевое состояние не блокирует экспорт, а предупреждает.
- **Профиль проекта** (лимиты костей, влияний, треугольников, веса текстур) задаётся один
  раз и используется всеми экранами: статусами, бюджетами предпросмотра, ограничением
  нормализации весов.
- **Перо**: нажим управляет силой кисти в скульптинге и покраске; палец — только навигация
  камерой, чтобы ладонь не рисовала.

## Состояние

Минимальный набор, который держит интерфейс:

- `document` — сцена, объекты, иерархия, материалы, скелеты, анимации; версионируется
  очередью команд (`undoStack`, `redoStack`).
- `selection` — режим (`object | mesh | material | animation | scene`), подрежим,
  выделенные объекты, уровень элементов (вершина/ребро/грань), выделенные элементы.
- `activeOperation` — параметры последней операции для карточки в правой панели.
- `viewport` — камера, режим отображения, видимость наложений (сетка, гизмо, каркас).
- `playback` — текущий кадр, диапазон, воспроизведение, активный клип, смешивание.
- `projectProfile` — целевой движок и бюджеты; входные данные для всех проверок.
- `jobs` — выполняющиеся фоновые задачи (запекание, симуляция, рендер) с прогрессом.

## Ресурсы

Иконки — Material Symbols Outlined (вес 400), в макете подключены с Google Fonts; во Flutter
использовать `Icons` / `Symbols`. Шрифт Roboto — системный для Material 3.
Собственных изображений в макетах нет: всё нарисовано формами и градиентами как заглушки
под вывод flutter3d.

## Что не входит в макеты

Экраны импорта с проверкой и чистки меша, а также диалога экспорта с проверками пока не
нарисованы. В плане разработки оба отнесены к фазе 1 и должны быть спроектированы до начала
работы над ней.
