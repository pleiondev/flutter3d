## 3. Каталог материалов как продукт

**Кто потребляет** (аудит 04:72-74 и план): C-ядро через генерируемый заголовок (176 `#define` из 33 материалов, 04:8); Dart-физика (`rigid_body.dart`, `FluidMedium.of`), effects, конвертеры (D5: IFC/MaterialX/glTF-имена → id с отчётом о несвязанном, plan:160), лаборатории (`f3d.experiment`: «substances by id»), двойники (материалы с внешними id, D4). Три из пяти обещанных читателей (звук, окклюзия, ткань) сегодня не подключены (04:103, review:386-388) — правило D18/решение 20 «свойство без читателя — ошибка» ещё не держится.

**Как валидируется по плану:** строка `source:` у каждой группы (обязательна, D7 review:1134); `*.verified.json` «as the check» (plan:160); conformance-проверка формы каталога; «estimates marked»; данные — от **двух исследовательских агентов** в scratchpad, ~100 жидкостей + ~100 твёрдых, «every value with a source» (plan:83, acceptance :174).

**Скептические замечания:**

1. `source` — строка. Она не проверяется ничем, кроме непустоты; `*.verified.json` по описанию сверяет каталог с самим собой (файл-снимок), а не с внешней базой. Данные, собранные LLM-агентами с цитатами, — известный класс риска: правдоподобная цифра с правдоподобной ссылкой. Для 33 текущих записей источники выглядят подлинными (CRC 97th ed., Del Grosso & Mader 1972 — `materials.dart:35-37, 65-69`), но это рукописные записи; масштабирование ×6 агентами меняет природу гарантии.
2. **Ответственность.** «Physics-grade» в сочетании с «for industry» означает, что интегратор может положить число в инженерное решение. MIT снимает гарантию юридически, но не репутационно. Нужна явная формулировка в README matter и CONTRACTS: «reference values for simulation; not for design or safety calculations», плюс поле `confidence`/`estimate` **в типе**, а не в комментарии (сейчас «estimate» — одно слово в комментариях).
3. **`PropertyLaw.at(T, p)` для 200 материалов × 6 групп** — это ~1000 законов. Источники температурных зависимостей есть у воды, воздуха, нескольких металлов; для большинства записей закон будет `constant` при 20 °C. Это допустимо (D5: «the 20 °C scalar is the value of that function at the reference state»), но тогда «every property is a function of state» — маркетинг для 90 % каталога. Стоит публиковать таблицу покрытия: какие свойства каких материалов имеют реальную T-зависимость.
4. **`externalIds`: IFC и MaterialX.** У сплавов нет CAS; IFC-материал — свободный текст `IfcMaterial.Name`; у MaterialX нет стандарта идентичности веществ. Карта id — правильная форма, но «converters bind IFC» требует IFC-импорта, который в 1.x (review:811, 1281). Значит, пространство `ifc` в 1.0 без потребителя — противоречие с решением 20, если lookup не считать читателем.
5. **200 — правильное ли число для 1.0?** Нет. Acceptance plan:174 «≥ 200 entries, each value with a source» измеряет объём, не верность. Предпочтительнее: ~40–60 записей, которые реально читает код (правило D18 как фильтр), проверенные человеком по CRC/IAPWS/ASM с номером страницы/таблицы в `source`, плюс открытая схема для плагинов (`<pluginId>.<name>`, уже есть). 200 агентных записей — объём для сравнения с конкурентами, а не продукт; его можно добавить в 1.x как отдельный пакет `flutter3d_matter_extended` с иным уровнем гарантии.

## 4. Детерминизм против точности

**Лаборатория.** Сегодня маятник — симплектический Эйлер при 1/60 с (`pendulum.dart:9-13, 84-88`), с честным комментарием о поправке амплитуды (:15-20: 2,3 % при 0,6 рад, 5,3 % при 0,9 рад). **Тестов против аналитики нет**: `pendulum_lab_run_test.dart:8-20` — порядковые («длиннее — медленнее»), :22-45 — Луна в 3 раза медленнее. Целевое: 3C «analytic tests (pendulum, projectile, orbit) in test/» (plan:167) и acceptance «a laboratory test runs the pendulum under `accurate` against its closed form within the documented tolerance» (plan:176-178). **Имя теста не зафиксировано, допуск не назван числом** — «documented tolerance» без числа. vision:44-46 обещает отчёт валидации законов в CI на сайте — в плане rc.1/rc.2 пункта нет (только 3C-тесты).

Критический нюанс: **`accurate` = Dart-движок, C-ядро остаётся float** (plan:166: «the core stays float; `accurate` means the Dart engine, documented»). Dart-движок **не имеет вращения твёрдых тел** (инвентарь 14:135: «Dart-fallback без вращения»); жидкости/тепло/огонь живут в ядре. То есть «точная» лаборатория в 1.0 — это точечные массы, `LiquidBody` (Dart, `flutter3d_physics/lib/src/fluid/liquid_body.dart:71`) и ткань; маятник на реальном шарнире с моментом инерции, гироскоп, волчок, термодинамический опыт — либо float, либо не на `accurate`. Это нигде не сказано пользователю. **Не проверено**: даст ли 3C Dart-движку вращение — в plan:167 такого нет.

Кросс-платформенная бит-точность под `accurate` явно **не** обещается (review:1111 «no cross-platform bit promise»), а под `deterministic` `parity_test.dart` сам говорит, что ответ «narrower than "the simulation is deterministic"» (`flutter3d_sim/README.md:56-58`). Для проверки работы студента на сервере это значит: лаборатория под `accurate` проверяется **не** реплеем-до-бита, а сравнением показаний с допуском — механизм, которого в плане нет (`DigestTrace` — бит-точный, `firstLabDivergence` сравнивает входы, не выходы).

**Двойник, 10 км.** Целевое: `originShift` при ~1 км, тест на 5 км (plan:98), абзац в CONTRACTS «precision relative to the camera, not to the origin» (review:1100-1101). Это утверждение о **виде**: геометрия float32 относительно плавающего origin, физика в ядре float, origin в double (09:50). Для одной площадки 1–3 км — достаточно; для линейного объекта 10–100 км два одновременно видимых узла на разных концах не получат заявленной точности, и заявления об этом нет. Тесты физики вдали от origin — 10–90 м (09:48); тест 5 км обещан для `Flutter3dView`, не для физики. **Численного утверждения («± X мм на Y км») в плане нет** — будет прозаический абзац.

Для двойника: ускорение авторинга сцены из USD; для лаборатории: D31 обещает редактирование `f3d.experiment` через MCP (plan:192, 194) — rc.1 по плану, но лаборатории на нём только в rc.2.

## 6. Вердикты и минимальные добавления

**Двойник.** rc.1 — к пилоту не готов: нет адаптеров, истории, правил, viewer kit, облаков точек; один пример. rc.2 — пилот возможен в формате «вьюер + воспроизведение телеметрии одной площадки + правила окраски + секции/измерения», при условии, что интегратор пишет адаптер, хранилище и аутентификацию сам. Это пилот 3D-слоя, не двойника.

**Лаборатория.** rc.1 — возможна лаборатория, написанная Dart-разработчиком по образцу маятника, с LTI-запуском без оценки; учителю делать нечего. rc.2 — школьный пилот на двух экспериментах с оценкой через LTI возможен, если 5F и 4J дойдут и будет измерен реальный iPad/Chromebook.

**Пять минимальных добавлений для пилота двойника:**

1. Один опубликованный адаптер (`MqttExternalStateInput` на `mqtt_client` или REST-поллер) в примере 4K — иначе D4 читается как «принесите всё своё».
2. Рецепт/тип истории: лента на час/сутки с файлом-индексом по метке времени и скраббинг через `RunTimeline` — уже почти есть в `lab_incident`, нужно оформить и задокументировать.
3. Референсное приложение двойника в репозитории на месте висячих ссылок на `flutter3d_lab_twin` (пять мест) — насос/бак из `flutter3d_elements` с одним реальным источником и одним `Rule`.
4. Числовое утверждение о точности в CONTRACTS и физический тест на 5 км (не только вид): «позиции ±X мм на расстоянии Y от origin площадки, физика float32 относительно сдвинутого origin».
5. `GeoOrigin` (lat/lon/alt + ENU) как запись в `WorldProperties`/`Level` — назван в D4, отсутствует в D-таблице, стоит день.

**Пять минимальных добавлений для школьного пилота:**

1. Аналитический тест маятника с именем и числом: например `packages/flutter3d_education/test/lab/pendulum_period_test.dart`, период при θ₀ = 0,1 рад за 100 периодов в пределах 1e-4 относительно T₀(1 + θ₀²/16 + …), и ограничение дрейфа энергии; число — на страницу Education.

3. `Semantics` и `textScaler` во вьюере уроков и панели лаборатории — перенести из 4J в step 4.1 (объём — часы).
4. Фикстура `pendulum.f3d.experiment` с одним редактируемым параметром и ожидаемыми показаниями, читаемая тестом — доказать формат D31 до редактора.
