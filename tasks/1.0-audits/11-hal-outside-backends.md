# Можно ли написать пятый бэкенд снаружи (ветка 1.0.0, 2026-10-09)

Заметки агента.

## Вердикт

Пятый бэкенд снаружи репозитория написать **можно, и до зелёного `runDeviceConformance` его довести можно без форка**: `GraphicsDevice`, энкодеры и `ShaderLibrary` — `abstract base` классы, которые наследуют (`extends`), конструкторы хэндлов опубликованы в `package:flutter3d_hardware/backend.dart`, и эта библиотека входит в semver-снимок `api/flutter3d_hardware.api`; `DeviceRegistry.addBackend`/`addPresenter` подключают бэкенд в `openDevice`/`Flutter3dView` без правок `flutter3d_app`, а `flutter3d_conformance` — обычный pub-пакет на `package:test` с публичным раннером и фабрикой устройства. Что **не получится без форка**: (а) материалы плагинов и `.f3dmat` — и run-time (`RuntimeShaders`), и build-time (`flutter3d_build_hooks`) захардкожены на четыре секции бандла; (б) голден-тесты движка через `flutter3d_testing` — CPU-бэкенд зашит; (в) обещание «новый член приходит с телом» нарушено для `PassEncoder`/`ComputeEncoder`/`TransferEncoder` (38 абстрактных членов, включая feature-gated), так что минорный релиз HAL может сломать внешний бэкенд; (г) единственный гайд для автора бэкенда (`site/content/core/backends.md`) описывает API 0.8 и в нескольких местах неверен. Шейдеры — отдельная большая работа (105 обязательных stage'ей, перевод GLSL своими силами), но это известное и честно задокументированное ограничение, а не скрытое.

## 1. Реализуемая поверхность

**Проверено чтением.**

- `GraphicsDevice` — `abstract base class … with TextureAllocator` (`packages/flutter3d_hardware/lib/src/graphics_device.dart:47`), явное обещание «implementable outside, stays so through 1.x» (:42-46). Абстрактных членов ~22: форматы/origin/depthRange/preferredSampleCount (:52-94), `createCubeRenderTarget`, `shaders`, `loadShaders`, `createPipeline`, `uploadGeometry`, `overwriteGeometry`, `createTextureFromPixels`, `overwriteTexture`, `createCubeTextureFromPixels`, `beginFrame`, `onFrameComplete`, `beginRenderPass`, `readback`, `releaseGeometry`, `dispose`, `features`, `limits`, `textureFormatSupport`, плюс `createTexture`/`releaseTexture` из `TextureAllocator` (`render_target_pool.dart:91-145`). Всё feature-gated (compute, buffers, queries, transfer, mapBuffer, render bundles, async pipelines, `lost`/`isLost`, labels, release*) имеет тело по умолчанию `throw refuse(...)` или no-op (:486-760). `backendName` по умолчанию `$runtimeType` (:660).
- Миксины-возможности: `SynchronousBufferReadback` (`base mixin on GraphicsDevice`, :772) — `readBufferSync` **не обязателен**, conformance трактует отсутствие как отказ (`flutter3d_conformance/lib/src/capability_checks.dart:692-698`); `EncodedImageUpload` (`encoded_image.dart:28`); `LoadedShaderLibrary` (`shader.dart:223`); `RenderBundleEncoder`/`CommandEncoder` (`command_encoder.dart:615, 653`).
- **`PassEncoder` — `abstract base mixin class` (`command_encoder.dart:122`), но из его членов 38 абстрактны и только три (`pushDebugGroup`/`popDebugGroup`/`insertDebugMarker`, :582-588) имеют тела.** Абстрактны и feature-gated: `multiDraw`, `multiDrawIndirect`, `executeBundles`, `begin/endPipelineStatisticsQuery`, `setDepthBias`, `setColorWriteMask`, `setDepthClamp`, `bindStorageBuffer`, `bindStorageTexture`, `bindUniformBytes`, `drawIndirect`, `drawNonIndexed`, `begin/endOcclusionQuery` (:444-571). То же у `ComputeEncoder` (`compute.dart:125-225`) и `TransferEncoder` (`transfer.dart:53-135`). README (`packages/flutter3d_hardware/README.md:64-80`) обещает: «a new member arrives with a body … a member without a default body … waits for a major». Для устройства это так, для энкодеров — нет. **should** (становится blocker при первом миноре, добавляющем член энкодера).
- Хэндлы `final` с приватными конструкторами (`texture.dart:48`, `shader.dart:73,149`, `compute.dart:28,86`, `resources.dart:500,535`, `geometry_buffer.dart:45`); бэкенд создаёт их через `wrapTexture/wrapShader/wrapPipeline/wrapGeometry/wrapStorageBuffer/wrapComputePipeline/wrapQuerySet/wrapRenderBundle/forgetShader` (`backend_handles.dart:7-11`). Поле `backend` везде `Object` с обоснованием (`texture.dart:104-111`, `shader.dart:97-102`) — нетипизированный SPI, кастуется внутри бэкенда. **nice** (типизировать нельзя без генерика, обоснование разумное).
- `backend.dart` — публичный API под semver: библиотека есть в снимке `packages/flutter3d_hardware/api/flutter3d_hardware.api:5-23` («a change here is a semver decision»). Правило «internal, builtin and testing libraries are reached only on purpose» его **не касается**: regex ловит только `internal|builtin|testing` (`tool/structure/boundaries.dart:58-64`), и правило сканирует только `packages/`/`apps/` репозитория. Но ни README, ни CHANGELOG (кроме упоминаний :16, :116), ни `docs/CONTRACTS.md` не говорят словами «backend.dart стабилен». **should**.
- `DeviceFeature` — закрытый набор (приватный конструктор `capabilities.dart:58`, `values` :516); бэкенд не может объявить свою фичу — это правильно. `DeviceLimits`/`TextureFormatSupport` имеют публичные const-конструкторы (:724, :864). `UniformMemberLayout`/`StageBindings` — typedef-рекорды (`shader.dart:41-49`). `VertexLayoutDescriptor` — `final` value-класс, `null` = «по рефлексии» (`vertex_layout_spec.dart:236`).
- Гайд для автора есть — `site/content/core/backends.md` («Writing a HAL backend»), но он **устарел**: `supportsX`-геттеры в примере (:80-139), `abstract interface class PassEncoder` (:242), `present`/`readPixels` (:273-275), `TextureHandle?` из `createTextureFromPixels` (:209), в таблице имён продублированы и расходятся строки Vertex/Lighting/Post (:403-411). Скилл `packages/flutter3d_hardware/skills/flutter3d-hardware-backend-contract/SKILL.md` тоже про `present` и «draw() без индексов рисует ничего» (:39-40, :55). **should**: это первое, что читает автор.

## 2. Шейдеры

**Проверено** (чтением, субагент + выборочная перепроверка).

- Устройство получает **F3SB `ShaderBundle`**: заголовок (имя, sdk, список stage) + `Map<String, ByteData> sections` с **открытыми строковыми ключами** (`shader_bundle.dart:56-65, 164-171`); именованы только `impeller`/`webgl`/`webgpu`/`material` (:95, :99, :136, :148). Секцию `'vulkan'` добавить ничто не мешает. Бэкенд, компилирующий из GLSL сам (как CPU из Dart), может читать только `material`/список stage.
- Translate-пайплайн **не является публичной точкой расширения под другой язык**: `compile.dart` даёт `loadShaders({from})` (сырые GLSL + манифест, `flutter3d_shaders/lib/src/source_package.dart:26-73`) и `compileStage`, который гонит `glslangValidator -V` → `naga` и возвращает только `(wgsl, offsets)`; SPIR-V живёт во временном каталоге (`lib/src/wgsl_compiler.dart:68-140`). Ни SPIR-V, ни MSL/HLSL наружу. Переиспользуемы `loadShaders` и `resolveIncludes` (`glsl_translate.dart:55`) — поверх них внешний бэкенд ставит свой glslang/spirv-cross. **should**: отдать SPIR-V и целевой язык параметром.
- **Build-хуки захардкожены на четыре секции**: `flutter3d_build_hooks/lib/src/material_compile.dart:318-332`, штамп кэша `flutter3d_build/lib/src/material_build.dart:141-145`. `.f3dmat` проекта никогда не получит пятую секцию. **blocker** для материалов проекта/плагинов на пятом бэкенде.
- Контракт биндингов — **по именам**, не по слотам (`command_encoder.dart:330-372`); численной таблицы set/binding нет, Vulkan-бэкенд назначает сам (как делает WebGPU-пакер). Таблицы `stageBindings`/`uniformBlocks` доступны только через `flutter3d_shaders/internal.dart`, который объявлен «not covered by semver for applications» (`internal.dart:1-19`) и в allowlist структуры перечислены поимённо четыре бэкенда (`boundaries.dart:103-114`). Внешний пакет правило не сканирует, но semver-оговорка остаётся. **should**: вынести `stageBindings`/`uniformBlocks` в публичную библиотеку для бэкендов. `F3D_*`-дефайны документированы только `F3D_MEDIUMP` (`shaders/PRECISION.md`); варианты (`PbrOpaque` и т.п.) — отдельные entry points. `docs/CONTRACTS.md` про шейдеры молчит. **nice**.
- Ядро требует все **105** entry points (`flutter3d_shaders/lib/flutter3d_shaders.dart:41-148`) + 4 compute при `compute` (:30-35); conformance падает на любом отсутствующем (`shader_link_checks.dart:6-23`), рендерер — `StateError` (`flutter3d_core/lib/src/engine/render/renderer_resources.dart:45-55`). Без `flutter3d_shaders` собрать бэкенд технически можно (`kept` nullable), но GLSL и имена нужны всё равно — все четыре зависят.
- **Run-time материалы плагинов**: `flutter3d_plugin_runtime/lib/src/data/runtime_shaders.dart:84-275` — `switch` по cpu/webgl/webgpu/impeller, прочее — `RuntimeShadersException` «not a backend this engine can compile a shader for at run time» (:272-276); `RuntimeBackends.normalize` узнаёт имена по префиксам (:65-74). **blocker**: пятый бэкенд не получит плагинные материалы; нет SPI «компилятор материалов для бэкенда» (подозрение: его место — рядом с `materialCompiler:` у `registerCpuBackend`, `backend_native.dart:50`).

## 3. Подключение

**Проверено.**

- `openDevice({width, height, DeviceRegistry? registry})` (`flutter3d_app/lib/src/backend_native.dart:93-106`, web :137-150), `platformDevices()` создаёт свежий реестр (:46-67); `addBackend` — «последний добавленный пробуется первым» (`device_registry.dart:57-80, 96`). Значит `platformDevices()..addBackend('Vulkan', open)..addPresenter<VkDevice>(p)` делает пятый бэкенд предпочтительным **без правки `flutter3d_app`**. Оговорка: app всегда импортирует и регистрирует четыре штатных (:14-16), «по умолчанию для платформы» = пустой `DeviceRegistry()` + свои записи; это нормально.
- `FramePresenter` — публичный typedef функции `Widget Function(GraphicsDevice, TextureHandle, {BoxFit fit, FilterQuality quality})` (`scene_surface.dart:18-24`, в `flutter3d_app.api:155`); реализуется любым замыканием, текстура → виджет — дело бэкенда (Impeller: `GpuFrameImage`, CPU: `CpuFrame`). Бэкенд регистрирует презентер **из своего пакета, не завися от `flutter3d_app`** — образец `flutter3d_impeller/lib/src/gpu_backend_registration.dart:14-31`, `flutter3d_webgl/.../webgl_backend_registration.dart:17-29`. `presenterFor` → `Object?`, каст `as FramePresenter?` в `backend_native.dart:124-128`; несовпадение сигнатуры ловится только в рантайме. **nice** (план 2A типизирует).
- `Flutter3dView(device:, devices:, presenter:)` (`flutter3d_view.dart:333, 340, 404`); открытие захардкожено 1280×720 (:481-483). Одолженное устройство без реестра/презентера → `ArgumentError` (:129-135).
- `DeviceLoss` обрабатывается обобщённо: подписка `engine.device.lost` (:552), `_onLoss` (:557-586) — restored → пересоздать рендерер, recoverable → ждать, иначе reopen из `engine.devices`. Типов устройств не проверяет.

## 4. Доказательство

**Проверено.**

- Conformance публичен: `typedef DeviceFactory` (`flutter3d_conformance.dart:113`), `runDeviceConformance({backend, makeDevice, ownShaders})` (:212), списки `coreChecks`/`shaderChecks`/`conformanceChecks` (:256, :282, :443). Зависимости — `test` (не `flutter_test`), презентер и голдены не нужны. Образцы: `flutter3d_cpu/test/conformance_test.dart`, `flutter3d_webgl/test/conformance_test.dart` (`@TestOn('browser')`, с `ownShaders`); Impeller — скрипт `flutter3d_impeller/tool/conformance.sh`.
- **Отказы считаются непоследовательно**: часть проверок `decline()` → skipped (`compute_checks.dart:20-21`, `vertex_texture_checks.dart:246-248`), часть — тихий `return` при `!features.has(...)`, который засчитывается как pass (`core_checks.dart:327`, :448; `stencil_checks.dart:33`, :200; `render_target_checks.dart:31`; `draw_checks.dart:362`), вопреки заголовку библиотеки (:44-47) и тексту гайда про «41 of 41 без скрытого». `checkCapabilitiesAreHonest` (`capability_checks.dart` ~751) держит список фич в обе стороны — это хорошо. **should**.
- `flutter3d_testing` **прибит к CPU**: `renderFrame` → `cpuTestDevice` (`lib/src/render_frame.dart:66`), `testReplay` (`test_replay.dart:266`), `pubspec.yaml:37`; device-agnostic `drawOnce(device:)` намеренно не экспортирован (`draw.dart:7-11`). Голдены движка на своём бэкенде через этот пакет не прогнать. **should** (для владельца, требующего «plug into the testing package» — blocker).
- Внешнего референсного бэкенда нет; `tool/webgpu_spike/lib/src/webgpu_spike_device.dart:156` — умышленно неполный спайк. `FakeBackend extends GraphicsDevice with SynchronousBufferReadback` (`testing_fake_backend.dart:109`) переопределяет ~45 членов — не «минимум», а полная запись. **nice**: минимальный `HeadlessNullDevice` как пример.
- Правила структуры сканируют только репозиторий, внешний пакет не задевают. Но: «every package that implements GraphicsDevice is named in SUPPORT» опирается на regex `\bimplements\b … GraphicsDevice` (`tool/structure/detectors.dart:983-986`), а все бэкенды пишут `extends` (`cpu_device.dart:43`, `gpu_device.dart:42`, `webgl_device.dart:52`, `webgpu_device.dart:174`) — **правило никогда не срабатывает** (self-test :2135-2140 использует `implements`, который против `base`-класса не компилируется). «the engine names no backend» проверяет только `flutter_gpu`/`flutter3d_impeller` (`rules.dart:766-800`). «hardware names no graphics API» — только слово `flutter_gpu` (:675-698). Все три предполагают, что бэкенды тут; внешнему не мешают, но первое — баг. **should**.

## 5. Скрытые связки

**Проверено** (grep по `is GpuDevice|is WebGlDevice|is CpuDevice|runtimeType|Platform.is|kIsWeb|defaultTargetPlatform|backendName ==`).

- Единственная проверка типа: `device is CpuDevice ? device.readHdrPixels : null` в диагностике (`flutter3d_app/lib/src/diagnostics/render_extensions.dart:310`) — остальные бэкенды получают «unread». Безвредно. Прочие импорты `flutter3d_cpu` в app/editor_core — утилиты (PNG, `builtin.dart` для превью материалов), не выбор бэкенда.
- `runtimeType` — только в сообщениях об ошибках; `Platform.isWindows`/`defaultTargetPlatform`/`kIsWeb` — shell, storage, загрузка ассетов; `DeviceClass` строится из `DeviceTraits` (флаги вроде `samplesBc`) + замер, не из имени (`flutter3d_core/.../device_class.dart:104, 167-172`).
- GPU-тайминги — через `device.onGpuTimings` (`renderer.dart:2063`), вызывается только при фиче; `reversedDepth` — `DeviceFeature` (`capabilities.dart:478`), а не формат. Readback — два RGBA8-лейаута, задокументировано (`graphics_device.dart:394-442`).
- Кэш шейдеров по имени бэкенда — **не найден** (hits `backendName` только в отказах/реестре).
- «Report unsupported» как путь: задокументирован (README:50-58 «A missing capability is a refusal, never a substitution», `graphics_device.dart:527-541`) и проверяем (`checkCapabilitiesAreHonest`, `refusal_checks.dart`). Да, это легитимный и тестируемый путь для каждой опциональной фичи.
- Асимметрия: регистрация WebGPU и презентер CPU живут в `flutter3d_app` (`backend_web.dart:94-113`, `backend_native.dart:54-65`), а Impeller/WebGL — в своих пакетах. Внешнему бэкенду доступен только второй образец; он работает.
- Главные связки — в §2: `RuntimeShaders` и build-хуки (**blocker** для плагинных материалов).

**Чего в плане нет, чтобы пятый бэкенд остался возможным:**
1. **blocker** — SPI компилятора материалов для бэкенда (run-time `RuntimeShaders` + секции в `material_compile.dart`), иначе плагины не работают на пятом бэкенде.
2. **should** — тела по умолчанию (`throw refuse(...)`) для feature-gated членов `PassEncoder`/`ComputeEncoder`/`TransferEncoder`, иначе обещание README не выполняется.
3. **should** — явная фраза о стабильности `backend.dart` в README/CHANGELOG; публикация `stageBindings`/`uniformBlocks` вне `internal.dart`; `compileStage` с выдачей SPIR-V/целевого языка.
4. **should** — `flutter3d_testing.renderFrame(device:)`/экспорт `drawOnce`; единообразный `decline()` в conformance.
5. **should** — переписать `site/content/core/backends.md` и SKILL под 1.0; починить regex `implementsGraphicsDevice`.
6. **nice** — минимальный пример внешнего бэкенда (или шаблон `flutter3d create plugin --kind backend`: `PluginKind` сейчас только renderStep/effect/genre/element/tool, `flutter3d_build/lib/src/plugin_template.dart:31-68`); строка SUPPORT.md о том, как внешний бэкенд объявляет уровни поддержки; явная пометка в плане rc.1, какие из 2A-изменений ломают внешние реализации.

Ничего не менялось; тесты не запускались.
