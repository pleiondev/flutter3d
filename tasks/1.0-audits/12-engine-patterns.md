# Публичные API модульных 3D-движков: практики и сожаления (сверка для flutter3d 1.0, 2026-10-09)

Заметки агента. Все факты проверены по официальным докам/исходникам 2026-10-09. Несколько вводных из задания устарели — отмечено «[устарело]».

## 1. Bevy (0.20, 2026-10-08)

Регистрация: `trait Plugin { fn build(&self, app: &mut App) }`, `App::add_plugins`, `PluginGroup` (`DefaultPlugins.set(PbrPlugin{..})`); паника при двойном добавлении (https://docs.rs/bevy/latest/bevy/app/trait.Plugin.html). Кадр [устарело]: `RenderGraph`/`ViewNode`/`add_node_edge` **удалены в 0.19** — проходы стали системами в расписаниях `Core3d` с `.after(Core3dSystems::MainPass)`, `RenderContext` — SystemParam (https://bevy.org/learn/migration-guides/0-18-to-0-19/). Фазы `RenderSystems`: ExtractCommands→PrepareAssets→Queue→PhaseSort→Prepare→Render (https://docs.rs/bevy/latest/bevy/render/enum.RenderSystems.html). Материалы: `trait Material` + `#[derive(AsBindGroup)]` + `MaterialPlugin<T>`; в 0.20 шейдеры WESL, `#import` убран (https://bevy.org/news/bevy-0-20/). Sim/view: `RenderApp`, `ExtractSchedule`, `PipelinedRenderingPlugin` — кадр N рисуется, пока N+1 симулируется. HAL: только wgpu; `RenderCreation::Manual` принимает чужой device. Версии: 0.x, «breaking version every ~3 months», deprecated живёт один релиз (https://github.com/bevyengine/bevy/blob/main/README.md). Единицы: Y-up, −Z вперёд, lumens; «1 unit = 1 m» нигде не записано. Первая сцена: `DefaultPlugins` + spawn `Mesh3d/MeshMaterial3d/Camera3d`.

## 2. Godot 4 (4.7)

Регистрация: GDExtension (`gdextension_interface.h`, `extension_api.json`, `.gdextension` с `compatibility_minimum/maximum`); `EditorPlugin` через `plugin.cfg`, `add_import_plugin(EditorImportPlugin)`, `add_scene_format_importer_plugin`, `EditorScenePostImport._post_import` (https://docs.godotengine.org/en/stable/engine_details/engine_api/gdextension/what_is_gdextension.html). Кадр: графа нет; `RenderingServer` (RID, асинхронный поток), `RenderingDevice` низкого уровня, `CompositorEffect._render_callback` с пятью точками `PRE_OPAQUE…POST_TRANSPARENT`, только Forward+/Mobile (https://docs.godotengine.org/en/stable/classes/class_compositoreffect.html). Шейдеры: `#include` только `.gdshaderinc`, `VisualShaderNodeCustom._get_code`. Sim/view: `_process` / `_physics_process` (60 Гц), `thread_model` помечен «Experimental… not recommended». HAL: `RenderingDeviceDriver` — внутренний C++, внешний бэкенд невозможен; физика — наоборот, `PhysicsServer3DManager.register_server` + `PhysicsServer3DExtension`. Версии: «loosely follows SemVer», минорные ломки «в очень узких областях» допускаются, deprecated снимается в мажоре; LTS (https://docs.godotengine.org/en/stable/about/release_policy.html). Обещание ABI: «ext for 4.2 works in 4.3, not vice-versa», но 4.0→4.1 сломали бинарно (https://docs.godotengine.org/en/stable/tutorials/migrating/upgrading_to_godot_4.1.html). 3→4: конвертер, «большая часть вручную». Единицы: метры, правая, Y-up; физические единицы опционально (`use_physical_light_units`, лм/лк/нит, `CameraAttributesPhysical`).

## 3. three.js (r186)

Регистрация: реестра нет; `GLTFLoader.register(parser => plugin)` с хуками `_invokeOne/_invokeAll` (https://github.com/mrdoob/three.js/blob/dev/examples/jsm/loaders/GLTFLoader.js). Кадр: `EffectComposer` + `Pass.render(renderer, write, read)` только для WebGLRenderer; для WebGPURenderer — `RenderPipeline` (бывший `PostProcessing`, переименован в r183), `pass(scene, camera)`, `renderOutput()`; ресурсы не декларируются, эффекты — дерево узлов (https://github.com/mrdoob/three.js/blob/dev/src/renderers/common/RenderPipeline.js). Материалы: `Material.onBeforeCompile` — строковые замены GLSL, официально «recommended approach… is TSL»; TSL/`NodeMaterial` (`colorNode`, `Fn`, `uniform`) компилируется в WGSL/GLSL (https://github.com/mrdoob/three.js/wiki/Three.js-Shading-Language). Sim/view: нет, граф сцены и есть состояние. HAL: `new Renderer(backend)`, абстрактный `Backend` экспортирован — сторонний бэкенд структурно возможен, стабильность не обещана. Версии: r-номера, «release per month», «deprecated code is removed in ten releases», Migration Guide в wiki; фактический ритм замедлился до 2–3 мес (https://github.com/mrdoob/three.js/wiki/Migration-Guide). Единицы: без фиксированной; Y-up, −Z; `physicallyCorrectLights`→`useLegacyLights` (r150)→по умолчанию off (r155)→удалено; `PointLight.intensity` в канделах.

## 4. Babylon.js (9.0, 2026-03)

Регистрация: `ISceneComponent { register(); rebuild(); dispose() }`, `SceneComponentConstants`, 24 стадий (`_beforeCameraDrawStage` …), но `scene._addComponent` помечен `@internal` (https://github.com/BabylonJS/Babylon.js/blob/master/packages/dev/core/src/sceneComponent.ts). Кадр: `PostProcess` + `PostProcessRenderPipeline`/`PostProcessRenderEffect`; новый `FrameGraph` (`FrameGraphTask.record()`, текстуры «managed by the frame graph», `scene.frameGraph = fg`), `NodeRenderGraph` с редактором; доки: «implementation is not yet fully complete» (https://doc.babylonjs.com/features/featuresDeepDive/frameGraph). Материалы: `MaterialPluginBase` (`getCustomCode(shaderType, shaderLanguage)` в точках `CUSTOM_FRAGMENT_MAIN_END`, GLSL+WGSL) — санкционированный путь; `NodeMaterial`, `ShaderMaterial` (https://doc.babylonjs.com/features/featuresDeepDive/materials/using/materialPlugins). Sim/view: `runRenderLoop(() => scene.render())`, Observables. HAL: `AbstractEngine`/`ThinEngine`/`WebGPUEngine`/`NativeEngine` (bgfx); контракт для чужого engine не документирован. Версии: мажор раз в год; правило «cannot add code that will break backward compatibility», deprecated «never removed» (https://github.com/BabylonJS/Babylon.js/blob/master/contributing.md). Единицы: без фиксированной; **левая система по умолчанию**, `scene.useRightHandedSystem` «not the main mode»; glTF-лоадер вставляет корневой узел с отражением, форумы — зеркальные экспорты, сломанный `createNormals` в RH (https://forum.babylonjs.com/t/gltf-models-appear-mirrored-after-switching-our-app-from-rhs-lhs-seeking-root-cause-best-practice-fix/61098). Свет: `INTENSITYMODE_LUMINOUSINTENSITY/ILLUMINANCE/LUMINANCE`, только для PBR.

## 5. Filament (1.77)

Регистрация: нет плагинов; `Engine` — фабрика (`createRenderer/View/Scene`), компоненты на `utils::Entity` через `RenderableManager/LightManager/TransformManager::Builder` (https://raw.githubusercontent.com/google/filament/main/filament/include/filament/Engine.h). Кадр: **закрыт** — `FrameGraph` лежит в `filament/src/fg/`, не в `include/`; единственные крючки — настройки `View` (`setColorGrading`, `setPostProcessingEnabled`, `setRenderTarget`), `Renderer::renderStandaloneView`, материалы домена `POST_PROCESS`/`COMPUTE` (https://github.com/google/filament/tree/main/filament/src/fg). Материалы: `.mat` (`material {}` + `fragment { void material(inout MaterialInputs) }`), `shadingModel: lit|subsurface|cloth|unlit|specularGlossiness`, `matc -p -a` в `.filamat` на бэкенд; `filamat::MaterialBuilder` для рантайма; gltfio — `ubershader` против `jit` провайдера (https://google.github.io/filament/Materials.md.html). Sim/view: отдельный render thread, `Renderer::render()` только из main thread. HAL: `backend::Platform` публичен (`createDriver`), `Driver` — в `include/private/`; чужой бэкенд только в дереве. Версии: 1.x, релиз каждые ~7 дней, `RELEASE_NOTES.md` с меткой «API Change», «use tools from the same release», `UTILS_DEPRECATED` (https://raw.githubusercontent.com/google/filament/main/RELEASE_NOTES.md). Единицы: lux для directional, lumen/candela для point/spot, cd/m² для IBL, `Camera::setExposure(f/16, 1/125, ISO100)` (https://google.github.io/filament/Filament.md.html).

## 6. Unity SRP / URP / HDRP (Unity 6)

Регистрация: `ScriptableRendererFeature.Create()/AddRenderPasses()` в инспекторе рендерера; HDRP — `CustomPass` + `CustomPassVolume`, `CustomPostProcessVolumeComponent.injectionPoint` (https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@17.0/api/UnityEngine.Rendering.Universal.ScriptableRendererFeature.html). Кадр: `ScriptableRenderPass.renderPassEvent` (`AfterRenderingOpaques` …); RenderGraph: `RecordRenderGraph(RenderGraph, ContextContainer)`, `AddRasterRenderPass<PassData>`, `CreateTexture` (память «just before the first pass that needs it»), `ImportTexture` (не вырезается), автоматический culling и слияние в native render pass (https://docs.unity3d.com/6000.0/Documentation/Manual/urp/render-graph-write-render-pass.html). Старый `Execute` — «Compatibility Mode», «Unity no longer develops… the path that doesn't use render graph» (https://docs.unity3d.com/6000.0/Documentation/Manual/urp/compatibility-mode.html). Шейдеры: Shader Graph с Targets URP/HDRP/Built-in — «not all blocks compatible»; surface shaders только Built-in; три разных ShaderLibrary. Фрагментация: Render Pipeline Converter «doesn't support custom shaders», «irreversible»; стратегия 2026 — Built-in deprecated в 6.5, HDRP без новых фич, URP по умолчанию (https://unity.com/topics/render-pipelines-strategy-for-2026; https://discussions.unity.com/t/unified-rendering/1519264). Sim/view: ECS + `Entities Graphics` поверх `BatchRendererGroup`. HAL: `GraphicsDeviceType` закрыт; плагинам — `IUnityGraphics` + `IssuePluginEvent`. Версии: пакеты SRP привязаны к версии редактора, `[Obsolete]` (CS0618→CS0619), API Updater. Единицы: метр, **левая** Y-up; HDRP `LightUnit {Lumen, Candela, Lux, Nits, Ev100}`, URP — без единиц.

## 7. Unreal Engine 5

Регистрация: `.uplugin` с `Modules[{Name, Type, LoadingPhase}]`, `PostConfigInit` для шейдерных плагинов, `AddShaderSourceDirectoryMapping` в `StartupModule` (https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-shaders-in-plugins-unreal-engine). Кадр: RDG — `FRDGBuilder::AddPass(RDG_EVENT_NAME, Params, ERDGPassFlags, lambda)`, `CreateTexture` только дескриптор, transient aliasing (`r.RDG.TransientAllocator`), `QueueTextureExtraction`, `r.RDG.CullPasses`, `BEGIN_SHADER_PARAMETER_STRUCT` + `RENDER_TARGET_BINDING_SLOTS` (https://dev.epicgames.com/documentation/en-us/unreal-engine/render-dependency-graph-in-unreal-engine). Санкционированный крючок — `FSceneViewExtensionBase` с `SubscribeToPostProcessingPass`. Sim/view: render thread «a frame or two behind», `FPrimitiveSceneProxy` как зеркало компонента, `ENQUEUE_RENDER_COMMAND`, tick-группы `TG_PrePhysics…` (https://dev.epicgames.com/documentation/en-us/unreal-engine/threaded-rendering-in-unreal-engine). Материалы: граф + `Custom` HLSL-узел («prevents constant folding»), Material Functions/Layers; Substrate — Beta, «use caution when shipping». HAL: `FDynamicRHI` + `IDynamicRHIModule::CreateRHI`; сторонний RHI-модуль не документирован. Версии: semver нет, `UE_DEPRECATED("5.1", …)`, сроки удаления не опубликованы, вендоры плагинов собирают бинарник на каждый минор (https://docs.redpoint.games/docs/support/engine_support_policy). Единицы: **сантиметры, Z-up, левая, X вперёд**; свет — cd/lm/lux/EV100 (https://dev.epicgames.com/documentation/en-us/unreal-engine/using-physical-lighting-units-in-unreal-engine).

## 8. wgpu / wgpu-hal (30.0)

Слои: `wgpu` → `wgpu-core` (валидация) → `wgpu-hal` («sole obligation is portable behavior», минимум валидации). `wgpu_hal::Api` — 23 ассоциированных типа (Instance…AccelerationStructure), но `const VARIANT: Backend` — закрытый enum, так что чужой HAL-бэкенд невозможен (https://docs.rs/wgpu-hal/latest/wgpu_hal/trait.Api.html). Зато с 25.0 есть `wgpu::custom` — `InstanceInterface/DeviceInterface/…`, `Instance::from_custom` — официальный путь для стороннего бэкенда уровня API (https://docs.rs/wgpu/latest/wgpu/custom/index.html). Возможности: `Features` (паника на неподдержанное), `Limits::defaults() / downlevel_defaults() / downlevel_webgl2_defaults()`, `DownlevelCapabilities{flags, limits, shader_model}.is_webgpu_compliant()`, `Backends` bitflags (https://docs.rs/wgpu/latest/wgpu/struct.Limits.html). Версии: «breaking version every three months»; с v22 (2024-07) мажорные номера и «fully adhere to Semantic Versioning»; MSRV bump = breaking (https://github.com/gfx-rs/wgpu/releases/tag/v22.0.0). Координаты: «coordinate systems of D3D and Metal», depth [0,1], framebuffer y вниз.

## 9. bgfx (API 166)

`RendererType::Enum {Noop, Direct3D11/12, Metal, Vulkan, OpenGL/ES, WebGPU, Agc, Gnm, Nvn}`; внутренний `RendererContextI` (~40 чистых виртуалов, `src/bgfx_p.h`) и compile-time таблица `s_rendererCreator[]` со `static_assert` по `RendererType::Count` — внешний бэкенд только правкой enum/таблицы/`config.h` (https://raw.githubusercontent.com/bkaradzic/bgfx/master/src/bgfx.cpp). `Caps{supported, limits, homogeneousDepth, originBottomLeft}` — бэкенд-разница вынесена в флаги (https://raw.githubusercontent.com/bkaradzic/bgfx/master/include/bgfx/bgfx.h). Кадр: views как упорядоченные корзины, `setViewOrder`, `setViewMode`, `submit(ViewId, program, depth)`, `Encoder` на поток, `frame()`. Шейдеры: `shaderc` из `.sc` + `varying.def.sc` в бинарь на профиль; рантайм принимает только бинарь. Версии: `BGFX_API_VERSION`, rolling master, тегов нет; C99 ABI через `bgfx_get_interface(version)` возвращает NULL при несовпадении (https://raw.githubusercontent.com/bkaradzic/bgfx/master/src/bgfx.idl.inl). Хиральность: `bx::mtxLookAt(..., Handedness::Left)` по умолчанию, depth-конвенция читается из `Caps`.

## 10. O3DE (26.05)

Регистрация: Gem = `gem.json` (`dependencies: ["Atom>=1.0.0"]`, `compatible_engines`) + `AZ::Module` с дескрипторами компонентов (https://docs.o3de.org/docs/user-guide/programming/gems/manifest/). Кадр: единственный среди всех **декларативный** граф — `.pass` JSON (`Slots`, `ImageAttachments{Lifetime: Transient|Imported}`, `PassRequests`, `Connections{AttachmentRef{Pass, Attachment}}`), `RenderPipelineDescriptor .azasset`, Gem вставляет проходы из `FeatureProcessor::AddRenderPasses` или `AddPassRequestToRenderPipeline(pipeline, path, referencePass, before)` (https://docs.o3de.org/docs/atom-guide/dev-guide/passes/pass-template-file-spec/). Материалы: `.material`→`.materialtype` (с `version` и `versionUpdates`)→`.shader`→AZSL (HLSL + SRG), `.materialpipeline` порождает шейдеры на пайплайн. Sim/view: компоненты → `FeatureProcessor::Simulate/Render` → Views → Draw Lists. HAL: **бэкенд = Gem**, `FactoryManagerBus::RegisterFactory`, выбор `-rhi` (https://github.com/o3de/o3de/blob/development/Gems/Atom/RHI/Code/Include/Atom/RHI/Factory.h). Версии: `YY.MM` дисплей + semver в `engine.json` с `api_versions{editor, framework, launcher, tools}`, уровни Stable/Preview/Experimental (https://docs.o3de.org/docs/contributing/release-versioning-and-terms/). Единицы: метр, правая, **Z-up**; `PhotometricUnit {Lumen, Candela, Lux, Nit, Ev100…}`.

## 11. Stride (4.4, 2026-10-09)

Регистрация: `GameSystemBase` в `GameSystems`, `EntityProcessor<TComponent, TData>` через `[DefaultEntityComponentProcessor]`, скрипты `SyncScript/AsyncScript` (https://doc.stride3d.net/latest/en/manual/engine/entity-component-system/usage.html). Кадр: `GraphicsCompositor` — сериализуемый граф `ISceneRenderer`/`SceneRendererBase.DrawCore`, `RenderFeature` (Collect→Extract→Prepare→Draw), `RenderStage` («stages don't define order, the compositor does») (https://doc.stride3d.net/latest/en/manual/graphics/rendering-pipeline/render-features.html). Шейдеры: SDSL — HLSL с наследованием/миксинами (`shader A : Base { override … }`), `compose`, `stream`, `.sdfx` с условными миксинами; 4.4 переписал компилятор на SPIR-V (https://doc.stride3d.net/latest/en/manual/graphics/effects-and-shaders/shading-language/shader-classes-mixins-and-inheritance.html). Sim/view: XNA-цикл `Update`→`Draw`, не параллельно; Bepu `FixedTimeStep`. HAL: `GraphicsDevice` — partial-классы по API, выбор MSBuild-дефайнами, чужой бэкенд только в движке. Версии: документировано «minor updates don't contain breaking changes», но 4.4 (минор) убрал OpenGL, переименовал `Utilities`, переписал компилятор (https://doc.stride3d.net/latest/en/ReleaseNotes/ReleaseNotes.html). Единицы: метр, правая, Y-up, свет без единиц.

## 12. PlayCanvas (2.23)

Регистрация: ESM `class X extends Script { static scriptName; initialize(); update(dt) }`, `ComponentSystemRegistry.add`, `AppOptions.componentSystems` (https://developer.playcanvas.com/user-manual/engine/standalone/). Кадр: `FrameGraph`/`FramePass`/`RenderPass` есть, но `@ignore`; публично — `CameraComponent.framePasses = [scenePass, tintPass]` и `CameraFrame` (bloom/ssao/taa/dof); пользователь сам ведёт render targets и оба языка GLSL+WGSL (https://developer.playcanvas.com/user-manual/graphics/posteffects/cameraframe/custom-passes/). `Layer.onPreRender/onPostRender` удалены в 2.0 → события `scene.on('prerender:layer')`. Материалы: `ShaderMaterial({vertexGLSL, fragmentGLSL, vertexWGSL, fragmentWGSL})`, чанки через `material.getShaderChunks(SHADERLANGUAGE_GLSL).set('emissivePS', …)` с `shaderChunksVersion` (2.8); `Material.chunks` deprecated (https://github.com/playcanvas/engine/releases/tag/v2.8.0). HAL: `GraphicsDevice` базовый, `Webgl/Webgpu/NullGraphicsDevice`; `createGraphicsDevice` жёстко знает три; свой — только `app.init({graphicsDevice})`. Версии: semver; 2.0 (2024-08) — большой разрыв (WebGL1, Scripts 1.0, Phong), `Debug.deprecated`/`Debug.removed` в debug-сборках (https://github.com/playcanvas/engine/releases/tag/v2.0.0). Единицы: метр, Y-up, −Z; «правая» только на форуме.

## 13. OpenUSD / Hydra (26.08)

Регистрация: `plugInfo.json` + `PlugRegistry` для всего — `HdRendererPlugin` (`CreateRenderDelegate`), `HdSceneIndexPlugin` (`loadWithRenderer`), `SdfFileFormat` (`formatId`, `extensions`), `ArResolver` (`AR_DEFINE_RESOLVER`) (https://openusd.org/release/api/class_plug_registry.html). Бэкенд: `HdRenderDelegate` — `GetSupportedRprimTypes`, `CreateRenderPass`, `CreateRprim/Sprim/Bprim`, `GetMaterialRenderContexts`, `GetCapabilities` (https://raw.githubusercontent.com/PixarAnimationStudios/OpenUSD/release/pxr/imaging/hd/renderDelegate.h). Hydra 2.0: `HdSceneIndexBase` + фильтрующие индексы заменяют scene delegate; 25.11 — новый путь по умолчанию, 26.03 — runtime-предупреждение (https://forum.aousd.org/t/deprecating-hydra-1-eventually/2804). Кадр: `HdTask::Sync/Prepare/Execute`, `HdxTaskController` уже deprecated. `Hgi` (GL/Metal/Vulkan, WebGPU — только форк Autodesk) подклассируется без политики. Материалы: `UsdShade` с render contexts (`outputs:ri:surface`), `UsdPreviewSurface` для обмена, MaterialX, `SdrRegistry` (Ndr удалён в 25.08). Версии: `YY.MM`, `HD_API_VERSION` = 103 со списком ломок, ABI не обещан; AOUSD Core Spec 1.0 (2025-12) (https://aousd.org/uncategorized/core-spec-announcement/). Единицы: `metersPerUnit` (по умолчанию 0.01!), `upAxis` Y|Z, правая; UsdLux — 1 нит базис.

## 14. flutter_scene (0.24.3, 2026-10-09)

[устарело сильно] Теперь «3D game engine», монорепо: `scene` (чистый Dart, `.fscene`), `flutter_scene_rapier/box3d`, `_soloud/_fmod`, `_net`, `_editor`, `_mcp`; importer свёрнут в `package:flutter_scene/build_hooks.dart`, `.model` заменён на `.fsceneb`, `dart run flutter_scene:init` (https://pub.dev/packages/flutter_scene/changelog). Регистрация: `Component` на `Node`, контракты физики/аудио как pluggable-backend; общего реестра плагинов нет. Кадр: фиксированные 18 шагов, «you do not reorder them»; `CustomRenderPass { stage: afterScene|beforeToneMapping|afterToneMapping|afterAntiAliasing; inputs: {depth, normals, shadowMap} }` и `PostEffect(insertion:)` (https://github.com/bdero/flutter_scene/blob/master/POST_PROCESSING.md). Материалы: `.fmat` (`material{}` + `fragment{ Surface(inout MaterialInputs) }`, `shading_model: lit|unlit`) или `ShaderMaterial` на сыром GLSL ES 3.00; без языка моделей освещения (https://github.com/bdero/flutter_scene/blob/master/MATERIALS.md). Sim/view: `Scene.update(dt)` опционален, `SceneView` владеет тикером. HAL: шим выбирает flutter_gpu (Impeller) или встроенный WebGL2 по `dart.library.*` — компиляция, не интерфейс; внешний бэкенд невозможен. Версии: 0.x, «minor releases can carry breaking changes» (0.23 сменил winding). Единицы: Y-up, метры подразумеваются, свет радиометрический («scalar multiplier»). Тоньше flutter3d в: плагинах, графе кадра, HAL, единицах, версионировании.

## 15. Omniverse / Unity Industry / gz-rendering

Kit: расширение = папка с `extension.toml` (`[dependencies]`, `[[python.module]]`, `[[native.plugin]]`), `omni.ext.IExt.on_startup/on_shutdown`, semver у расширений («breaking → major»); RTX — Hydra render delegate `omni.hydra.rtx`; USD — единая модель данных (https://docs.omniverse.nvidia.com/kit/docs/kit-manual/latest/guide/extensions_advanced.html). Launcher и приложения Create/Code/Machinima объявлены legacy (2025-07), SDK через GitHub/NGC (https://developer.nvidia.com/omniverse/legacy-tools). Unity Industry (2023) = Unity 6 + Asset Transformer (ex-Pixyz) + Asset Manager; Unity Simulation deprecated (https://support.unity.com/hc/en-us/articles/14416305057684). gz-rendering: `RenderEnginePlugin` через `GZ_ADD_PLUGIN`, `gz::rendering::engine("ogre2")`, `GZ_RENDERING_PLUGIN_PATH` — рендер-бэкенд как внешний плагин (https://gazebosim.org/api/rendering/9/renderingplugin.html).

## Синтез

### Повторяющиеся практики (у движков с хорошей репутацией API)

1. **Один объект регистрации с явным build-хуком** (Bevy `Plugin::build`, Kit `IExt.on_startup`, Stride `GameSystemBase`, USD `plugInfo.json`). flutter3d: да — `.f3dplugin` + реестры.
2. **Манифест с версией контракта, а не версией движка** (Godot `compatibility_minimum`, O3DE `engine_api_dependencies`/`api_versions`, Kit semver расширений, bgfx `bgfx_get_interface(version)`→NULL). flutter3d: да — `PluginApiVersion`, отдельный номер у `flutter3d_plugin_api`.
3. **Именованные точки вставки, а не позиции** (URP `RenderPassEvent`, HDRP injection points, Godot `effect_callback_type`, flutter_scene `RenderStage`, UE `SubscribeToPostProcessingPass`). flutter3d: да — `RenderAnchor` перед/после каждого прохода.
4. **Транзиентные ресурсы объявляются графом, память выдаётся по времени жизни** (Unity `CreateTexture` + culling, RDG `TransientAllocator`, O3DE `Lifetime: Transient|Imported`, Babylon FG «managed by the frame graph»). flutter3d: частично — `ResourceId` есть; культивация/алиасинг — неизвестно.
5. **Декларативное описание пайплайна файлом** (O3DE `.pass`/`.azasset`, Stride compositor-ассет, Babylon `NodeRenderGraph`). flutter3d: нет (граф собирается кодом).
6. **Материал = декларация + одна функция поверхности, компилятор на бэкенд** (Filament `.mat`+`matc`, O3DE `.materialtype`+AZSL, flutter_scene `.fmat`). flutter3d: да — `.f3dmat`.
7. **Версия у формата материала с миграторами** (O3DE `materialTypeVersion`/`versionUpdates`, PlayCanvas `shaderChunksVersion`). flutter3d: запланировано (`.f3dmat` получает версию в 1.0).
8. **Расширение материалов через точки, а не через правку строк** (Babylon `MaterialPluginBase`, Stride `compose`, PlayCanvas чанки с версией). flutter3d: да — открытый реестр моделей освещения.
9. **Явная граница sim/render со снимком** (UE scene proxies, Bevy Extract, O3DE FeatureProcessor, Filament render thread, bgfx `frame()`). flutter3d: да — view читает только опубликованное состояние.
10. **Возможности как флаги, не как исключения** (wgpu `Features/Limits/Downlevel`, bgfx `Caps`, USD `GetCapabilities`). flutter3d: да — capability flags.
11. **Бэкенд реализуется снаружи через тот же путь, что и свои** (O3DE RHI-Gem, Hydra render delegate, gz-rendering плагин, wgpu `custom`). flutter3d: да — HAL в списке «implementable interfaces», четыре бэкенда через `flutter3d_hardware`.
12. **Conformance-набор на каждый бэкенд** (wgpu CTS, `DownlevelCapabilities.is_webgpu_compliant`). flutter3d: да — `flutter3d_conformance`.
13. **Deprecation с именованной версией удаления и инструментом миграции** (Unity API Updater, Godot «removed in next major», Babylon «never removed», three.js «ten releases»). flutter3d: запланировано — `@Deprecated` с версиями + `dart fix`.
14. **Физические единицы света и экспозиция камеры** (Filament, HDRP, UE, O3DE, Godot opt-in). flutter3d: да — lux/candela по контракту.
15. **Единицы и хиральность записаны в одном документе** (Godot, O3DE, UE явно; Bevy, PlayCanvas, Filament — нет). flutter3d: да — `CONTRACTS.md`.
16. **Импорт как плагин с реестром форматов** (USD `SdfFileFormat`, Godot `EditorImportPlugin`, three.js `GLTFLoader.register`, Bevy `AssetLoader::extensions`). flutter3d: да — реестр форматов + `convert`.

### Сожаления

1. **Bevy: ломка каждые 3 месяца, граф рендера удалён в 0.19, `#import`→WESL в 0.20** — нет 1.0 через шесть лет. flutter3d: противоположный выбор — строгий semver с 1.0.
2. **Unity: три пайплайна с несовместимыми шейдерами**, конвертер «не поддерживает custom shaders», в 2026 сворачивают HDRP и Built-in. flutter3d: один материал компилируется на все четыре бэкенда — да.
3. **Unity: RenderGraph заменил `Execute`, старый путь — Compatibility Mode «winding down»**. flutter3d: неизвестно, были ли переписаны проходы между 0.x; в 1.0 ломка только в мажоре.
4. **three.js `onBeforeCompile`**: строковые патчи GLSL, «countless parametric materials that do not communicate», кэш программ игнорирует условия — заменён TSL. flutter3d: да, патчей строк нет.
5. **Babylon: левая система по умолчанию** → отражающий корневой узел на glTF, зеркальные экспорты, сломанные нормали в RH. flutter3d: правая Y-up с первого дня — да.
6. **Godot: 3→4 без полной автоматики; 4.0→4.1 сломал GDExtension бинарно**, обещание «только вперёд» и пометка «experimental». flutter3d: C-ядро объявлено внутренним, обещание на Dart API — да.
7. **Unreal: нет semver, вендоры собирают на каждый минор; Substrate в Beta годами**; единственный стабильный крючок — `FSceneViewExtension`. flutter3d: да (semver), но расширения кадра у flutter3d шире одного крючка — проверить, что все они обещаны.
8. **Filament: граф кадра закрыт, «use tools from the same release»**, релиз каждую неделю с «API Change». flutter3d: граф открыт — да.
9. **Stride: документировано «no breaking in minors», 4.4 ломает**. flutter3d: правило «структуры» и API-snapshots в CI — да (запланировано).
10. **PlayCanvas 2.0: `Layer.onPreRender` удалён, `Material.chunks` удалён**, пользователь custom pass ведёт GLSL и WGSL сам. flutter3d: один GLSL транслируется в WGSL — да.
11. **USD: `metersPerUnit` по умолчанию 0.01**, ABI не обещан, Hydra 1→2 растянут на годы. flutter3d: метры явно — да; миграция формата через цепочку миграторов — запланировано.
12. **Единицы не записаны** (Bevy, PlayCanvas, Filament, three.js). flutter3d: записаны — да.
13. **Бэкенд только в дереве** (bgfx таблица, Stride дефайны, Godot driver, wgpu-hal `VARIANT`). flutter3d: нет этой проблемы — да.
14. **flutter_scene: 0.x, «minor can break», winding сменён в 0.23**, HAL выбирается компиляцией. flutter3d: противоположно — да.

Не найдено несмотря на поиск: официальная фраза Bevy о правой системе и о плане 1.0; политика Epic о стабильности между минорами; официальная политика Unity о сроке удаления `[Obsolete]`; слово «right-handed» в доках PlayCanvas и Filament.
