# The API breaks and their migrations before 1.0.0-rc.1 (2026-10-09)

`1.0-rc1-plan.md` orders the work in waves. This document adds two things
to it. First, the order of the API breaks inside waves 2 to 3 and, for each
break, how a user's code and data move across it. Second, a wave **M** that
puts the migration tools in shape before wave 2 begins. It changes none of
the rc1-plan items. Where it adds work, the item names its owner from there.

## Where the tree stands (branch `1.0.0`, d3f905a56)

- Wave 2 has not started. The seven `@Deprecated` are all still present. The
  eight enums of A5 are enums and the four `sealed` types of A4 are sealed,
  and the snapshots hold 45 `sealed class` lines. `WebGlDevice.open` is
  synchronous and `GpuRenderBackend.open` takes no size. `TimeSource`, the
  `*Options` groups, `PluginGroup`, `MaterialParameters`, `SimulationProfile`
  and `EngineLog` do not exist. Foundation has `LinearColor` and the exception
  roots but no `ShaderCompileException` or `AssetNotFound`.
  `UnsupportedCapability` is in hardware.
- The migration machinery works. `0.8_to_1.0.yaml` has 1 538 entries:

  | kind | entries |
  |---|---|
  | manual | 721 |
  | rename | 286 |
  | none | 265 |
  | moved | 103 |
  | parameters | 66 |
  | import | 55 |
  | implementsToWith | 23 |
  | rewrite | 19 |

  The generator writes 614 fixes into 40 `fix_data.yaml` files.
  `generate_migrations.dart --check`, `migration_seed`, 56 snapshots and
  `tool/migrate_corpus.sh` are all in place.
- Two holes:
  1. `flutter3d migrate` rewrites Dart and pubspecs only. Levels, `.f3d`,
     `.f3dmat` and tapes are lifted when they are read and never on disk.
  2. 384 of the 721 manual entries say the same thing: the symbol was a
     backend's own and is not exported since 1.0. That covers cpu 167,
     webgpu 149, impeller 45, webgl 14, and 9 elsewhere. These entries make
     the guide read as "721 places by hand" when about 337 are real.
- Of the seven deprecated names, only `agxFull` has an entry. The other six
  get theirs when they are removed (step 2.0).

## Wave M: the migration tools (before wave 2, beside wave 1)

Owner: one agent on `flutter3d_build` (`lib/src/migrate/`,
`tool/generate_migrations.dart`, `lib/migrations/`), `flutter3d_lints`
(`lib/src/migration/`), `tool/structure/migration.dart`, `tool/api` and, for
M4 only, `flutter3d_foundation/lib/src/formats.dart`. It
touches nothing that wave 1's 1E edits in build. The two agree on the file
lists before they start, and M rebases onto 1E's fixes.

| # | Item | Size |
|---|---|---|
| M1 | **A kind for what went internal.** A new kind, `internal`: the symbol was public at `from` and has no replacement in the public surface. The entry carries `owner:` (the package) and an optional `instead:` (the kit that stays, e.g. `CpuStage` or `cpuUnlitStage`). The lints leave one diagnostic per import of the old library, not one per use. The guide shows one row per package with the count. The 384 entries move to it by a script that matches their guidance. An entry whose text names a replacement keeps `instead:`. The guide's headline then reads "N entries, M by hand" with M ≈ 337. | M |
| M2 | **A ceiling and honest numbers.** A rule in `tool/structure/migration.dart`: the count of `manual` entries may not grow past the number M1 leaves, unless the new entry sits on an allowlist with a reason. A break that could be automated by the kinds of M3 must use them. README, the guide and the site take their numbers from the table through the rule. "About two hundred places" and the `GameLoop` deprecation sentence go (A9 of wave 6 already lists the latter). | S |
| M3 | **Four automatic kinds** in the lints and the generator. Each has a before/after pair in `test/fixtures/migrate_0_8/` and a test.<br>• `regroup`: named arguments move into an options object, e.g. `Flutter3dView(x: 1)` becomes `Flutter3dView(view: ViewOptions(x: 1))`. Written for D9.<br>• `enumToClass`: a `switch` over the type that names every case gains `_ => throw UnimplementedError()` with a TODO. Written for A5, A4 and D8, where a type stops being an enum or sealed.<br>• `recordToClass`: `.$1`/`.$2` and named record fields become the class's getters from a field map. Destructuring patterns stay manual.<br>• `nullToThrow`: a call whose null check (`?? x`, `if (v == null)`) is right beside it gets a `try … on <Exception>` with a TODO, with the exception type taken from the entry. This cannot be a silent rewrite. The lint points at the exact place. | L |
| M4 | **`flutter3d migrate --data`.**<br>• Foundation gains `FormatSpecs`, a registry each owning package adds its `FormatSpec`s to. There are 32 today.<br>• The command walks the project by the registered extensions and lifts each file to the current version through `spec.lift`. It writes the file in place.<br>• Flags are `--dry-run` and `--backup`, and it reports `file: vN → vM` plus anything not carried over.<br>• The engine keeps reading every old version.<br>• `doctor` warns about files below the current version.<br>• The test builds a project from the oldest fixture of every format, migrates it, and compares the result with the newest fixture of each, byte for byte.<br>New file `lib/src/migrate/data.dart`. It reuses `FormatSpec.lift`/`versionOf` from `flutter3d_foundation/lib/src/formats.dart` and the fixture rule in `tool/structure/rules.dart`. | M |
| M5 | **A chain of tables.** `migrate` reads `pubspec.lock` and applies the tables from the version it finds: `0.8_to_1.0.yaml`, then `1.0.0-rc.1_to_rc.2.yaml`, and so on. The generator merges their fixes into one `fix_data.yaml` per package. After the tag `v1.0.0-rc.1` the first table is closed: a rule compares its stamp with the tagged one. `migration_seed` writes new breaks into the open table. The guide shows every table, newest first. | M |
| M6 | **A wider corpus.** `tool/migrate_corpus.sh` also takes the Dart blocks of `site/content` at `v0.8.5` (the quickstart, the tutorial and the cookbook pages) and builds each page into a small project, so the code a user copied from the site is migrated too. Every wave's integration runs the corpus with zero analyzer errors as the bar. | S |

Acceptance: `generate_migrations.dart --check` green; the manual count at
or below the ceiling; the fixtures of the four new kinds pass;
`migrate --data --dry-run` on the fixture project reports every file.

## Wave 2: the order of the breaks

### Step 2.0 (one agent, alone; after wave M, before 2A–2F)

Small, and every agent of 2.1 stands on it.

- In foundation, add `ShaderCompileException` and `AssetNotFound`, and move
  `UnsupportedCapability` from hardware with a `moved` entry. (`FormatSpecs`
  is M4's: it lands in foundation with `migrate --data`, which needs it
  first.)
- Remove the seven deprecated names (D12): `agxFull`, `Level.gravity` ×2,
  `oil` ×2, `legacyPluginMarkerKey`, `LoopPhase.elements`. Also remove the
  `ext.flutter3d.hotSwap` alias, which has no annotation. Each gets its
  `rename` or `none` entry (only `agxFull` has one today).
- Check decisions 1–11 of `1.0-api-review.md` against the tree and write one
  status line each here: `Material`/`Ray` and the nine duplicated names,
  `WorldPosition`, `Flutter3dGameLocalizations`, `ToolSpec`/`ToolResult`,
  `SettingsCubit` as a `ValueListenable`. An item that is not done goes to
  its package's owner in 2.1.

### Step 2.1 (2A–2F of the rc1-plan)

The owners stay as written. Each break uses the migration below. A break
that needs a kind other than the one listed changes this table in its
hand-back, and integration applies it.

| Break | Kind | Left to the user |
|---|---|---|
| A5 enum → open class with wire names (the eight + `GameState`, `RunState`, `RacePhase`) | none for constants (same syntax); `enumToClass` for switches | nothing |
| A4 / D8 sealed → `abstract base` (`Recorded`, `MaterialExpression`, `ActionBinding`, `TimelineCommand`, `CollisionShape`) | `enumToClass`; `implementsToWith` or a rewrite of `implements` to `extends` | nothing |
| A3 `DirectionalBackend`, `MixingBackend` → `base mixin class` with defaults; `PlacedEvent` → `abstract base` | `implementsToWith` | nothing |
| A6 one async `open({width, height})` | `parameters` (`add`, with the old default size as `value`) | `await` where `WebGlDevice.open` was synchronous |
| A4 `readBufferSync` → `testing.dart`, `createStorageBuffer` → `createBuffer(usage:)` | `moved`; `rewrite` | nothing |
| A9 `Vector3`/`Vector4` → `LinearColor` | `rewrite` (`LinearColor({target}.x, {target}.y, {target}.z)`) | nothing |
| A2 records → classes (128–175 lines matched, before filtering out private ones) | `recordToClass` | destructuring patterns |
| A7 / A10 / null-as-error | `nullToThrow` | the handling of the error |
| A8 removals | `rename` or `none` | nothing |
| D9 `DeviceOptions`, `ViewOptions`, `LoopOptions`, `PluginOptions` | `regroup` | nothing |
| D36 `StepSystems`/`StepContext` → `addSystem`/`LoopContext` | manual, with a before/after in `guidance:` | moving the systems |
| D39 `Material3D` on `MaterialParameters` | `parameters` where a name maps; manual otherwise | uniforms set by string |
| D40 `scripts` → `expressions` | data: the `.f3dplugin` migrator | nothing |
| D42 `Level.world`/`renderSettings` as patches | data: level v5 | nothing |
| D46 the project's plugin list as a `PluginGroup` | data: the project document's migrator | nothing |

**The contradiction settled.** The wave 3d decisions of the API review make
`MixingBackend` and `DirectionalBackend` opt-in interfaces. Readiness 2.2,
written later, makes them `abstract base` with defaults. Both hold if they
become `base mixin class` with defaults. They stay opt-in, since a backend
writes `extends AudioBackend with MixingBackend`. They also gain default
bodies, as A.1 requires. An `abstract base class` could not be mixed in
beside `AudioBackend`, so that form would lose the opt-in. The API review
gets a "superseded" line.

**Items no wave names,** given to the 2.1 owner of the package:

- The null-as-error sites the API review lists (:440–563). That is about 65
  after the 15 marked "probably absent", 22 of which A10 counts as left. Each
  is converted with a `nullToThrow` entry, or marked "absent" with a doc
  sentence.
- The bare `FormatException` throws, about 270 across 16 packages. They
  become `Flutter3dFormatException`. This is not a break if it extends
  `FormatException`, so check and write it down. If it does not, make it
  extend it.
- The leftovers of the API review's wave 3 integration (:650–683):
  - `StorageException extends ResourceException`;
  - the editor awaits `Storage.read`;
  - `light.type.name` in `project_format.dart:1583` becomes a wire name;
  - the envelope on `Ghost.toJson` and `.fmat`;
  - `BatonStream(this._holding)`;
  - the six members nothing calls.
- `GameEvents` removed (answer 3 of the API review). Its entry exists.

## The formats: one version per format per candidate

Nobody outside sees a version between two candidates, so each format moves
at most once per candidate. The wave that bumps it reserves the fields later
waves fill, and those fields are optional.

| Format | Version | Bumped by | Contents | Filled later |
|---|---|---|---|---|
| Level | v5 | 2C | `LinearColor` colors, `world` and `renderSettings` as patches, `behaviour` → `behavior`, `gravity` gone | `geoOrigin` and material ids, reserved in v5; 3F fills them without a v6 |
| `.f3drun` | +1 | 1A | `changedAt` | `ProbeReading` and external frames from 3F |
| `.f3dmat` | — | 3.0 | `version` and `updates` (D45); v1 and v2 read as before | — |
| `.f3d` | no bump | — | section 36 `physicalMaterials` is optional and skipped by old readers | — |
| `f3d.pipeline`, `f3d.experiment` | v1 | at birth | — | — |

Each bump comes with:
- a fixture under `test/fixtures/v<N>/`;
- a step in the `lift` chain;
- a line in the `migrate --data` report;
- a row in the guide.

## The gates

**Before the tag `v1.0.0-rc.1`:**

- `api_snapshot` clean and `tool/api_against_pub.sh` run;
- `migrate_corpus.sh` on the wider corpus: 0 analyzer errors;
- `migrate --data` on the fixture project carries every format;
- `rg '@Deprecated' packages/*/lib` empty; `sealed` only from the allowlist;
  `reexportedWhole = {}`;
- the manual count at or below M2's ceiling.

**The contracts rc.1 lands without an implementation:** `XrSession`,
`Rule`, `f3d.experiment`, `bindings:`, `f3d.pipeline`, the Wasm render ABI,
`PropertyLaw`.

- Each one is listed here with the sketch rc.2 fills.
- A change of shape between the candidates goes into
  `1.0.0-rc.1_to_rc.2.yaml` like any other break.

**After the tag:** `0.8_to_1.0.yaml` is closed (M5), and every new break
goes into the rc.1 → rc.2 table.

## The order on one line

M tools → 2.0 foundation types, deprecations out, decisions checked → 2A–2F
with their kinds → 2.2 → 3.0–3.2 with one bump per format → the gates → tag,
and close the table.
