# Stable contracts for 1.0.0

Decided with Dmitrii on 2026-10-08. **The release in preparation is numbered
1.0.0, not 0.9.0.** From it on we follow strict semver: a break comes only in
a major. Every public symbol is stable, with no `@experimental` exceptions.

## Where we start from (inventory of 2026-10-08)

- **Dart API.** There are about 2,700 public types across 46 packages.
  Class modifiers are applied consistently: 1,883 `final class`. No
  package imports another's `src/` from `lib/`.
- **What is missing.** No API diff runs in CI. Only 4 `@Deprecated`, none
  dated, and no `@experimental`. No 0.9.0 changelog section uses a
  "BREAKING" label.
- **86 `abstract interface class` types.** Each new member breaks every
  outside implementer.
- **Whole-package re-exports.** `flutter3d` re-exports core and hardware,
  `sim` re-exports physics, `app` re-exports editor_core.
- **The C core.** ABI 36 and snapshot 25 both demand an exact match. A
  snapshot is a memory dump.
- **Formats.**
  - `.f3d`, F3SB, `.f3dtrace` and lightmaps are read only at their exact
    version.
  - `.f3dmat` has no version.
  - The rest refuse files from the future but have never had a past to
    read.
- **Replays.** A tape of intents does not survive a change to the
  simulation (ARCHITECTURE §9.4).
- **Tooling interfaces.** About 204 MCP tools and 22 `ext.flutter3d.*`
  VM extensions, with no schema and no version.
- **Network.** The hello carries no protocol or simulation version.
- **Visual output.** 478 golden PNGs were re-recorded since August. Only
  4 of 46 pubspecs declare `platforms:`.

## Decisions

1. **Strict semver from 1.0.0.**
   - Patches fix bugs and add nothing that breaks.
   - Minors add.
   - Breaks happen only in a major, after a deprecation.
2. **Versions.** The engine ships under one number. The interface
   packages ship under numbers of their own, which rarely break:
   - `flutter3d_plugin_api`;
   - `flutter3d_hardware`;
   - the format schemas.
3. **The API is checked twice.**
   - Each package has `api/<package>.api`, a signature snapshot taken by the
     analyzer and committed. A structure rule classifies each change as
     an addition or a break, and demands a "Breaking" label in the
     CHANGELOG and the right version bump.
   - Before publishing, `dart_apitool` compares against the version on
     pub.dev.
4. **Deprecation lasts until the next major, and at least six months.**
   - Each `@Deprecated` names the version it was deprecated in, the one
     it goes in, and its replacement. A structure rule checks it.
   - `dart fix` data migrates callers.
5. **Everything public is promised.** Anything that is not ready is
   either finished or made private before 1.0.0.
6. **Implementable interfaces.** Outside code may implement these:
   - the HAL;
   - physics backends;
   - audio;
   - decoders and writers;
   - network transports;
   - storage;
   - plugins.

   New members on these arrive only with a default, through a `base`
   class or a mixin. Everything else is made `final` or `base`.
7. **Re-exports.** Barrels name what they re-export with `show` lists.
   `api/<package>.api` shows both levels.
8. **Formats.**
   - A 1.x engine reads every 1.x file, through chained migrators. Each
     version of each format has a fixture test.
   - Unknown fields are kept.
   - `.f3dmat` gets a version.
   - Shader bundles and caches are rebuilt automatically rather than
     refused.
9. **Replays.**
   - A tape records the simulation's version. Patches never change the
     simulation; a minor that changes it bumps the version.
   - A pose record is written beside the tape and always plays. An old
     tape of intents is refused honestly, with a reason.
10. **The C core.**
    - The header is documented as internal; the stable promise is the
      Dart API above it.
    - Native snapshots become field-by-field serialisation with
      migration, so saves survive updates.
11. **MCP tools and VM extensions** follow the same semver.
    - Names and JSON schemas are snapshotted in CI.
    - Additions come as new tools and optional arguments.
    - A renamed tool keeps its old name as an alias until the major.
    - The server announces its schema version.
12. **Network.**
    - The hello carries the protocol version and the simulation version.
      A mismatch is refused with a clear message.
    - Within a major the protocol only grows.
    - A match is formed only from builds with the same simulation
      version.
13. **A patch does not change the frame.**
    - Goldens move in a patch only for an obvious bug fix, written in
      the CHANGELOG.
    - In a minor the picture may change, marked in the CHANGELOG, and
      the old look comes back through a settings flag.
14. **Support.**
    - **Platforms.** `platforms:` goes in every pubspec, plus a platform
      × backend × support level matrix that CI checks.
    - **Versions.** We write down how many minors get fixes and which
      Flutter SDK window is supported.
    - **LTS.** One minor a year gets fixes for 18 months.
    - **flutter_gpu.** It is hidden behind our HAL. Its breaks are
      repaired in patches of the Impeller backend, and our API does not
      change.
15. **The GPU is covered as fully as possible**, with WebGL2 and WebGPU as
    the reference. Impeller's missing features are explicit TODOs that
    report unsupported, and they fill in without API changes. See
    `0.9-hardware-api.md`.
16. **Last changes to the frame and the tapes before 1.0.**
    - Particles and the platformer's crates take gravity from the world,
      so 22 m/s² against 24 is settled.
    - The air density by a fire comes from the world's temperature.
      The 1.2 inside the mist correlation stays, as part of that law.
    - Tapes and goldens are re-recorded.

## Order of work

1. Rename the release to 1.0.0: the versions in pubspecs, the CHANGELOG
   headings, the plans, the site. The branch is renamed by Dmitrii.
2. The snapshot generator (`tool/api`) and the structure rules. *Done*: 47 snapshots, 3 rules (snapshot, Breaking label, deprecation format).
3. Close the interfaces and add the `show` lists. A first set of snapshots is
   taken as the 1.0 contract.
4. Versions and migrators for the formats, versioned native snapshots,
   and the replay simulation version with the pose record. *Formats done*:
   `.f3d`, `.f3dsplat`, `.f3dtrace` and the lightmap read every version up
   to their own instead of only that one; the level, save, share bundle,
   telemetry upload and racing track lift older documents through a
   migration list (empty while each is at version 1); `.f3dmat` takes an
   optional `f3dmat <N>` line, absent read as 1. Each format has a v1
   fixture under its package's `test/fixtures/v1/`, and the 44th structure
   rule counts fixtures against every reader's constant, fails on an
   unlisted version constant and on a `!=` gate. Shader bundles are
   rebuilt, not migrated: the build's material stamp carries the container,
   section and language versions, and a bundle the runtime cannot read is
   refused with `ShaderBundleRefused.stale`. *Replays done*: `Demo` and the
   strategy `MatchDemo` record a `SimulationVersion` (engine number plus a
   per-genre constant, `platformerSimulationVersion` and its siblings) and
   a decimated `PoseRecord` that the racing ghost's `Playback` draws. A
   tape from another simulation is refused with `ReplayRefused`, which
   carries the poses, and the platformer ghost falls back to them. A
   format-1 match now opens as the pre-water simulation and its tape is
   refused with that reason. ARCHITECTURE §9.4 has the details.
   *Native snapshots done*:
   format 1.0, field by field in 17 versioned sections, ABI 37. Snapshots from before 1.0.0 are refused, so tapes that embed
   one (`ascent.f3drun`, the site's `platformer.f3drun`) are re-recorded
   with the rest.
5. MCP and VM schemas, and the network hello. *Schemas done*: `tool/api`'s
   `schema_snapshot` writes `api/<package>.mcp` for the three server
   packages (210 tools over four servers) and `api/<package>.vm` for
   `flutter3d_game` and `flutter3d_app` (29 extensions, one event);
   `tool/structure/schema.dart` classifies, and 2 rules hold them (snapshot,
   Breaking label with the schema version). `ToolTableServer` announces
   `schemaVersion` and takes `aliases`. *Network hello done*:
   `flame_multiplayer`'s `WireHello` carries the protocol (major and minor)
   and the game's simulation version. `PeerRoom` refuses a different major
   or simulation version with a sentence naming what to update to, and plays
   on the lower minor within a major. The relay keys rooms, parties and
   matches on `simulation=<n>`, refuses a different protocol major, and
   tells the client which version to update to. ARCHITECTURE §9.9 has the
   details.
6. The deprecation rule, the platform matrix, and `SUPPORT.md` with the
   LTS policy.
7. The last changes to the frame (16), then re-recording. *Code done*:
   the world-literal allowlist holds only the definitions, the mist
   correlation's 1.2 and the cistern's colour; what moves is listed in
   `0.9-release.md`, and the re-recording is still to do.
