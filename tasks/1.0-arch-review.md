# Architecture review before rc.1 (2026-10-08)

Five read-only reviews ran after waves 3–4: render/HAL/app;
sim/physics/net; formats/plugins/tools; the game layer; the package graph
and the docs. Their notes are in the session scratchpad under
`arch_review/`. This file is the plan that comes out of them.

## What holds

- **Layering.** The HAL knows nothing of the scene, and the backends don't
  import each other. Sim, core, physics and plugin_api contain no Flutter.
  There are no cycles in `dependencies:`.
- **Base classes and handles.** The HAL is base classes with defaults, and
  handle constructors live only in `backend.dart`. There is one exception
  root, with four families.
- **One render extension point:** step nodes and anchors. `addContributor`
  is used only for draws inside engine passes.
- **Physics:** no global backend; capabilities are mixins.
- **Events:** genre events have codecs, and `GameEvents` is gone.
- **Envelope and `.f3d`.** The format envelope (`FormatSpec.open`/`lift`,
  unknown keys) is sound. `.f3d` grows as planned and stays version 1 for
  0.8 readers.
- **Migrations.** The table, `fix_data` and the lints share one stamp.
  There is no `dart_mcp` in the public API.

## Must before rc.1: wrong at run time, silently

1. **Genre rollback and replays restore nothing.**
   - Each genre's state lives in its own `EcsWorld`, and `GenrePlugin`
     registers no `SnapshotPart`.
   - `rewindTo` on an empty world throws nothing. `EngineRollback` rolls
     back nothing, and the default `DeterminismCheck` always passes.
   - Fix:
     - a genre's state goes into the loop's snapshots;
     - `rewindTo` throws when nothing was restored;
     - `RunTimeline`, `RewindBuffer`, conformance and test_replay take a
       `SnapshotRegistry` or `EngineLoop`.
2. **Per-view TAA history breaks** when views are drawn by separate
   `render` calls. Velocity gets the current matrix and node history is
   shared. Fix: track each view's own last frame and its own node
   snapshots.
3. **The renderer ignores an origin shift.** History matrices stay in the
   old space, `IrradianceField.origin` doesn't move, and the particles
   aren't wired.
4. **`.f3d` writes Dart enum `.index`** (alphaMode, wrap, animation path
   and interpolation). Fix: code tables, plus a rule against `.index` and
   `values[` in format code.
5. **Re-exporting a `.f3d` bundle loses** its programs, prefabs, files and
   vendor sections (`F3dModelWriter`). The cloud's "download .f3d" goes
   through it.
6. **`TEMPSILENT` mutes all sound.** Fix: remove it, plus a rule that
   catches it.
7. **The publishing tiers are not a valid order.** In tier 1, plugin_api
   comes after its dependents. Tiers 2, 3 and 6 have dependencies inside
   the same tier. Fix: tiers L0–L9 from the graph, and a rule that checks
   topology.
8. **`FormatRegistry` and `VmExtensions` are never built** in
   `Flutter3dView`, so a plugin cannot register a format or an extension.

## Must before rc.1: contract shape (a break later)

9. **The sim/view boundary exists only as types.**
   - Frame phases can reach `world`.
   - `PublishedState.events` holds events that are not encoded.
   - `query` takes a closure.
   - No consumer exists.
   - (Decision A.)
10. **Decisions written down but not carried out:**
    - **Decision 4 in the HAL:** `createTextureFromPixels`,
      `createCubeTextureFromPixels`, `createCubeRenderTarget`,
      `readPixels`, `WebGlDevice.open`/`WebGpuDevice.open`,
      `EnvironmentMap.from*` and `openSpeakers` return null;
      `DeviceRegistry.open` throws a StateError.
    - **E.12:** `readBufferSync` is still on `GraphicsDevice`.
    - **Decision 11:** core has 78 colours typed Vector3/Vector4, and app
      has 8 more.
    - **A.1/A.2:** `ModelDecoder`, `ModelWriter`, `CheckedModelWriter`,
      `ModelDocument`, `EduDataSource` and `ActorStrides` are still
      interfaces or plain classes; `ModelFormat` is still an enum.
    - **Decision 2:** duplicate names remain: `ParticleSystem`, `Pose`,
      `Body`, `Heightfield`, `Selection`, `Tally`, `DocumentText`.
11. **Shapes that can't grow:**
    - `TraceEvent` is sealed, with one variant per HAL call;
    - `ToolContent` is sealed, with only text and image;
    - `F3dDocument.section()` and `SaveFile.read` return records;
    - `registerTimelineExtensions` returns void;
    - `PeerWire.listen` is single and returns void, and rollback messages
      share one namespace with the application's;
    - `ConstraintPhysics.constrain` returns `void Function()`;
    - `LightNode.maxLights`, `maxExtraLights` and
      `Renderer.shadowedLights` are `static const`.
12. **The 1.0 network core sits in a 0.x package** (`flame_multiplayer`)
    (decision B).
13. **Formats outside the contract:**
    - `.f3dtrace`, F3SB, `.f3dproj` (where `Enum.name` reaches the file),
      `VoxelWorld` (no version, no generator version);
    - the game_kit ghost tape, `convert --report`, the save-slot index,
      the settings file;
    - `.fmat` drops unknown keys.

    And the VM extensions:
    - `ext.flutter3d.hotSwap` breaks the naming;
    - 22 of 34 extensions have no result shape.
14. **Semver hole:** `src/` imports across packages. Core and all four
    backends import `flutter3d_shaders/src/*`, and the app imports
    `cpu/src`.
15. **Photometry is half done** (decision C).
    - `SkySettings.sunIntensity` is in the engine unit, while
      `Atmosphere.sunIntensity` is in lux.
    - `emissiveStrength`, ambient and probe intensity have no unit.
    - `toEngine`, `nitsPerUnit` and `luxPerUnit` are public.
    - The default `LightNode.intensity` is about 5790 cd.
16. **Deprecated in 1.0.0:**
    - 15 `supportsX` getters on the device and on `DepthTarget`;
    - `needsSurfaceBuffer`;
    - `ParticleSystem.emitFor`.

    Remove them, since this is the window for breaks.
17. **The `flutter3d:` pubspec key** draws a pub warning, and
    `publish_check` fails `flutter3d_post` on it (decision D).

## Must before rc.1: the way into the engine

18. **`Flutter3dView` is used by no one:**
    - the game facade doesn't export it;
    - the game example, the demos, the scaffold and the quickstart all
      build by hand;
    - `Scene3D` is a parallel path, with no loop, focus or lifecycle,
      and a `Vector4` clearColor (decision E).

    Also: the scaffold still adds `flutter_bloc` and points into the repo.
19. **`GameSettings` is still the 0.x shape:** a mutable
    `Map<String,double>` plus `Bindings`, against the Settings contract
    (decision F).
20. **Audio positions are `Vector3`** while the view hands out a
    `WorldPosition`, with no conversion between them.
21. **Docs claim what isn't true.**
    - ARCHITECTURE:
      - the package and app counts and the table (51/17; 12 packages
        missing);
      - :271, "build is not an engine dependency": it is reached through
        effects;
      - :258, "game re-exports neither";
      - GameLoop, FramePhase, `Material`, "three backends".
    - README: "forty-five packages / forty-two in 1.0".
    - CONTRACTS:
      - "every JSON document begins with the envelope";
      - "positions are WorldPosition", against about 436 public
        Vector3 signatures;
      - `Duration` used only at the boundary;
      - no `.name`.
    - SUPPORT: the Flutter floor is not set in every Flutter package.
    - The site: `renderer.addContributor`, `RenderTexture.create`,
      `Scene3D` in the quickstart.

## Should, ideally before rc.1

- **Device loss.** Nobody listens to it, so `Flutter3dView` goes blank on
  the web after a loss.
- **`_ViewState` leaks** when views are made fresh every frame, as
  `Scene3D` does.
- **Duplicate APIs:**
  - `Renderer.addMaterials` and `RendererSteps.addMaterials`;
  - `disabledPasses`, `stepsOff` and `without`/`only`;
  - `createTexture` and `createTextureWithDescriptor`;
  - `readPixels` and `readback`;
  - `WebGlDevice.open` and `openWebGl`;
  - the global `defaultDevices`;
  - `presenterFor` matching on `runtimeType`.
- **`EcsWorld` duplicates `SimWorld`.** Its `register` has no codec
  version, and the two iterate in different orders.
- **Events, origin and `WorldPosition`:**
  - an undeclared step event digests by name only;
  - the floating origin is half wired, with two APIs and no snapshot of
    `CollisionWorld`;
  - `WorldPosition` is used unevenly in physics (`moveKinematic`,
    `applyImpulse`, `join(anchor)`).
- **Simulation leaks:**
  - `LocalSimulation.submit` keeps only the last input and doesn't put it
    on the tape;
  - view types live in sim: `CameraRig`, `PhotoCamera`, `Lightmap`,
    `SequencePlayer`.
- **Genres:**
  - genres are not uniform: default kinds, `headless`, strategy without
    `publishTo`/systems, missing event descriptions;
  - `StepSystems` is ordered by number, against the loop's
    `after`/`before`;
  - the Flame cameras bypass `VirtualCamera`.
- **Input and audio:**
  - the old input paths remain: `FlameInputBridge(Bindings)`,
    `PadRoutes`, `slotKeys`;
  - audio has `AudioIssue` beside `Issue`, `Speakers.backend` typed as
    the concrete SoLoud class, and pause by muting the master bus;
  - `audio_core` declares Flutter without using it.
- **UI and globals:**
  - English and fixed colours remain in status_screens, the action
    labels and the touch widgets;
  - `postGameEvent` is a mutable global;
  - `StereoSurface` doesn't sit on `Flutter3dView`.
- **Packages:**
  - game_kit compiles C and downloads wgpu-native for every game, even
    though only ragdoll, wrecks and party need them (decision G);
  - effects → build pulls mcp and dart_mcp into games;
  - shooter and sim_mcp have a dev dependency on the unpublished
    demo_content, which pana won't resolve;
  - `flatDartPackages` doesn't cover physics, shaders, camera, post,
    editor_*, effects, physics_native, net or cpu.
- **Exceptions:** `ConstraintCycleError` and the `FormatRegistry` clash
  should be `PluginException`s; eight thrown `*Refused` types break §E.6
  (decision H).
- **MCP:**
  - `outputSchema` on 1 of 58 editor tools;
  - annotations on 14 of 154 model tools;
  - `declareSchemaVersion` ignored when called late;
  - schema versions start at 1.1/1.2.
- **CLI:** `--version` is hardcoded, `exit(64)`, and `--json` uses
  `schema` rather than `format`.

## Decisions (Dmitrii, 2026-10-08)

- **A. The sim/view boundary.** Fix the contract:
  - frame phases cannot reach `world`, and there is `LoopContext.published`;
  - events in `PublishedState` are encoded;
  - `query` has a named form;
  - one real consumer: the platformer's actor visuals.
- **B. The network core.** `PeerWire`, `RollbackSession` and `WireHello`
  move to `flutter3d_net` on the 1.0 line, and `flame_multiplayer` depends
  on net.
- **C. Units.** Emissive in nits; sky and ambient in lux. The defaults are
  recalculated so the pictures don't change, and the conversion constants
  are hidden.
- **D. The pubspec key.** `flutter3d:` becomes `flutter3d_plugins:`. The
  old key is read as a deprecated alias until 2.0.
- **E. `Scene3D`** is rebuilt on `Flutter3dView`. The quickstart, the game
  example and the scaffold start from `Flutter3dView`, and one genre demo
  moves to it.
- **F. `GameSettings`.**
  - Typed `SettingKey<T>` keys, namespaced;
  - volume per audio bus, and an `ActionMap` in place of `Bindings`;
  - immutable, with `copyWith`;
  - the settings file goes in the envelope.
- **G. The packages are split.**
  - ragdoll, wrecks and party leave `game_kit` for
    `flutter3d_game_physics`;
  - the effects build hook goes to a light package with no MCP.
- **H. `*Refused` becomes `*Exception`** for every type that is thrown,
  with rename migrations.
