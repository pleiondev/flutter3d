# Water, fire and bodies — public API proposal (2026-10-07, not implemented)

Requirements (Dmitrii): extensible; easy to plug into an app; intuitive yet
flexible.

## What is wrong today

`NativeWorld` is one flat class of `world.verb(handle, …)` calls. Each of the
nine games repeats the same wiring by hand: a private effects world stepped
and disposed by the game; `LiquidLook.asset` loaded and tinted; `FireView`
built with a fitted `baseWidth` (0.07…0.8); ground arrays with hidden rims
and a second array for the view; proxy bodies chased with
`setPosition/setVelocity`; nodes hidden by name; refuelling by resetting the
material; ignition by `setTemperature`; fire caps by writing state; light
caps; materials cloned field by field; spring slots tracked by index; five
copies of one sound loop.

## Principles

1. Descriptors for what a thing **is** (immutable, `const`, presets,
   `copyWith`, opaque — never `sealed`, so a new variant breaks nobody);
   handles for what **lives**.
2. Physical names, SI units; no "strength" or "amount" without a unit.
3. Defaults are cited data and the citation is in the doc; a value nobody
   can cite is a required parameter.
4. The simple path is the physical one: light a crate by holding a flame to
   it, hold a pool by an outlet, make a current with edges.
   `setTemperature` stays for initial conditions only.
5. Additive growth: optional named parameters, new presets, new factories;
   no positional parameters, no enums (const classes instead), no records
   as descriptors.
6. One owner per world; one-way coupling (`follow`) is first-class.

## Layers

```
flutter3d_physics_native   laws: NativeWorld + descriptors + handles
flutter3d_effects          FireView, LiquidView, looks, PhysicsHearing
                           + Elements: owns an effects world, follows game
                             objects, keeps nodes on bodies, draws, hears
flutter3d_audio_core       + HeldVoices: looping voices kept by key (place,
                             gain, rate), stopped when they go — the loop
                             five games copied; knows nothing of physics
the game                   says what is where; never steps, syncs,
                           refuels or caps anything
```

## A game's whole integration

```dart
final elements = await Elements.open(
  device: device, renderer: renderer, scene: scene,
  load: rootBundle.load, quality: ElementsQuality.of(phone: isPhone));
// each frame
elements.update(dt, eye: camera.worldPosition);

// a pond with a stream
final valley = elements.addWater(
  ground: Heightfield.sampled(origin: o, cell: 0.5, nx: 160, nz: 160,
      heightAt: terrain.heightAt),
  liquid: Liquid.water, bed: const Bed(roughness: Bed.naturalStream));
valley
  ..fillBasin(from: lagoon, level: 0.6)
  ..addSpring(at: spring, discharge: 0.6)
  ..addOutlet(NativeOutlet.weir(at: mouth, crest: 0.6, width: 3));

// a burning crate and a torch
final crate = elements.addBody(
  Solid.box(half, material: NativeMaterial.pineBoards), at: p, look: node);
elements.fires.ignite(crate, by: Igniter.match);
elements.fires.addBurner(at: torchHead, burner: NativeBurner.torch);

// a car's wheels through a ford, never written back to the car
for (final w in car.wheels) {
  elements.follow(() => w.pose,
      shape: NativeShape.cylinder(w.radius, w.width / 2));
}

// a current through the sea
sea
  ..setEdge(GridSide.west, NativeEdgeFlow.inflow(discharge: 100))
  ..setEdge(GridSide.east, NativeEdgeFlow.level(0));
```

## Core additions (`flutter3d_physics_native`)

- `NativeMaterial`: `copyWith`; optional `density`, `flameSpread` (Φ),
  `criticalHeatFlux`, `heatOfGasification`, `elasticModulus`,
  `poissonRatio`, `friction`, `restitution`, `rollingResistance`; cited
  presets `pine`, `oak`, `pineBoards`, `thatch`, `cardboard`, `coal`, …
- `NativeLiquidProperties`: `specificHeat`, `boilingPoint`, `temperature`,
  `copyWith`; `shallowPropertiesOf(water)`.
- Bodies: `NativeBodyType.kinematic`, `moveKinematic`,
  `submergedVolumeOf`, `buoyancyOf`.
- Fire: `NativeBurner` (+ `torch`, `brazier`, `campfire`, `candle`) with
  `addBurner/setBurnerFeed/removeBurner`; `NativeExplosion` (+ `.tnt`) with
  `explode`; `addHeatFlux` (a flame held to a face, ignition takes its
  time); `extinguish` (water only); typed `NativeFires` reader; events
  `burnerOut`, `exploded`, `ignitionStarted`, `wetted`.
- Water: spring handles (`addShallowSpring`), `NativeOutlet.weir /
  sharpWeir / culvert / drain` with `addShallowOutlet`,
  `NativeEdgeFlow.wall / free / inflow / level / critical` per `GridSide`,
  `setShallowWalls`, `setShallowRoughness`, `setShallowDepth`,
  `readShallowGround`, world-wide `NativeShallowSettings`.
- Vehicles and chains: `NativeWheelSpec` (width, rolling resistance) in
  place of the `NativeWheel` record; `setLinkSpeed` apart from
  `setLinkServo(stiffness, damping)`.

## Elements layer (`flutter3d_effects`)

`Elements` (open/adopt a world, `addWater`, `addBody`, `adopt`, `follow`,
`fires`, `hearing`, `wind`, `update`, `remove`, `dispose`, `world` as the
escape hatch); `Solid`; `Body`; `Liquid` = properties + `LiquidOptics`
(absorption/scattering shared by water surface and seabed); `Heightfield`
(`sampled`, `list`, `flat`); `Bed` (cited Manning n); `WallMask`;
`WaterBody`; `Fires` (`ignite`, `addBurner`, `explode`, `douse`,
`extinguish`, typed events); `Igniter` (`match`, `pilotFlame`,
`blowtorch`, `ember`); `Burner`; `Follower`; `ElementsQuality`.

Effects options instead of fitted numbers: `FireView` sizes each fire from
its own heat and patch (no `baseWidth`), `FireLights.clusters/perFire/none`
with photometric output and no caps, cited `smokeAlbedo`; `MistOptions`
instead of hiding a node by name; `LiquidLook.forLiquid(liquid)`;
`HearingScale` set by the game; `Hearing.wading`.

Audio: no new package. The keyed held-voice loop the games copy five times
is audio's own job and goes into `flutter3d_audio_core` as `HeldVoices`;
`PhysicsHearing` keeps handing out plain data (fires, falls, splashes,
wading), and a game maps one onto the other in a few lines. The default
element sounds ship as assets of `flutter3d_effects`.

## Not public

Core plumbing and layouts; raw float strides (kept as advanced, typed
readers are the documented path); descriptor internals
(`NativeShape.kind/first/second/third`, `NativeBodyType.code`, liquid ids);
view machinery (particle systems, vertex encoding, thresholds, node names);
no convenience wrapper that writes temperature to start or cap a fire; no
genre words.

## Decided (Dmitrii, 2026-10-07)

- `Elements` lives inside `flutter3d_effects`; sound stays in the audio
  packages (`HeldVoices` in `flutter3d_audio_core`), no new package.
- 0.9.0 is unpublished: old calls are replaced outright, no deprecation
  cycle.
- All nine games move to `Elements` in the same pass, dropping their own
  effects worlds, fitted numbers and crutches.

## Order

1. Core laws (heat, water, vehicles and chains) — in progress.
2. Core public API to this shape (descriptors, handles, outlets, edges,
   burners, explosions, kinematic bodies, wheel specs, servos).
3. Effects: FireView sized by heat, clustered photometric lights,
   `MistOptions`, `LiquidLook.forLiquid`, `HearingScale`.
4. `Elements`, and `HeldVoices` in `flutter3d_audio_core`.
5. The nine games on `Elements`, one at a time, each seen in the game.

## Open

- Followers must never feed back into the game (replays).
- `fillBasin` needs `setShallowDepth` in the core.
- `Elements.open(adopt:)` for games that step their own world (hollow,
  reef): follow, sync, draw and hear, but do not step.
- Burner, igniter and explosion presets need real citations first.
- 0.9.0 is not published yet (no tag), so the old calls can be replaced
  outright instead of going through a deprecation cycle.
