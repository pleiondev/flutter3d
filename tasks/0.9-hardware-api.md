# The hardware API for 1.0: audit and matrix

This is the audit of `flutter3d_hardware` against a complete modern GPU model.
WebGPU and WebGL2 together are the reference: anything either one can express
has to be expressible in this API. The release ships as **1.0.0** under strict
semver. `packages/flutter3d_hardware/api/flutter3d_hardware.api` is the
contract.

## Rules

- A capability is a `DeviceFeature`, counts and sizes are `DeviceLimits`, and
  what each format can do is `textureFormatSupport`. The fifteen pre-1.0
  `supportsX` getters, plus `maxAnisotropy` and `maxColorAttachments`, forward
  to these through `DeviceCapabilityForwarders`. Their docs mark them
  superseded but they are not `@Deprecated`: about sixty engine callers still
  use them, and `flutter analyze` fails on deprecation infos.
- When a backend lacks a capability, the feature is left out of `features`.
  The call throws `UnsupportedCapability` (feature, backend, reason) before
  anything reaches the driver. A `TODO(<backend>)` sits at the refusal.
- Four features are reserved: `rayQuery`, `meshShaders`, `bindlessResources`
  and `immediateData`. Each has a name and no calls, and no backend may report
  one.
- Stability is enforced by the repository's `tool/api` snapshot and the
  structure rules over it (see "The API is a snapshot" in CONTRIBUTING.md).
- Honesty is enforced by `capabilityChecks` in `flutter3d_conformance`.

## Before 1.0 (the audit)

The contract already had:
- 2D and cube textures, built from pixels or as render targets.
- A hand-supplied mip chain and render-to-mip.
- MSAA through the resolve target on a pass.
- MRT up to `maxColorAttachments`, and independent blend.
- Stencil, the blend constant, alpha-to-coverage and wireframe.
- Indexed draws with an instance count and an index window.
- Compute: storage buffers, pipelines, dispatch and `readBuffer`.
- Per-pass GPU timings, readback of RGBA8, compressed formats as sampling only,
  and anisotropy.

It was missing:
- Texture arrays, 3D textures and cube arrays, and rendering into a layer.
- General buffers and mapping, synchronous readback, and every kind of copy
  (buffer↔buffer, texture↔texture, buffer↔texture) plus an explicit resolve.
- Storage textures, and storage resources in render stages.
- Indirect draw and indirect dispatch, multi-draw, multi-draw-indirect,
  non-indexed draws, and base vertex / first instance.
- Occlusion, timestamp and pipeline-statistics queries.
- Render bundles.
- Depth bias, colour write masks, depth clamp, min/max blending and dual-source
  blending.
- Comparison samplers, LOD-clamped samplers and border-colour samplers, plus a
  W address mode.
- Integer, packed and depth-only formats.
- Integer uniforms (raw uniform bytes).
- A typed refusal.

The 1.0 surface adds all of these.

**Limits:**
- **Impeller:** colour attachments 4, or 1 on GLES; compute and storage limits 0.
- **WebGPU:** limits come from the device. Colour attachments are 4, anisotropy
  16, sample count 4, immediate data 0.
- **WebGL2:** limits come from `getParameter`.
- **CPU:** WebGPU defaults, except colour attachments 3 (set by the constructor),
  sample count 1, anisotropy 16, and storage offset alignment 4. The
  32-bit integer formats answer `none` (TODO: needs an integer plane).

**Known gap (WebGPU):** `WebGpuComputeStage` has `textures` and
`storageTextures`. `tool/generate_compute_shaders.dart` does not emit them
yet, so a compute texture bind answers false. That is honest under the
contract (false means undeclared), but compute texture binds cannot be used on
WebGPU until the generator emits those reflections.

## WebGL2

**Implemented:**
- arrays, 3D textures and rendering into a layer;
- texture writes, buffers, all copies, explicit resolve;
- mapped buffers (a copy) and `getBufferSubData`;
- non-indexed draws;
- `multiDraw` (through `WEBGL_multi_draw`, or a loop without it);
- base vertex and first instance (through the extension);
- render bundles (record and replay);
- depth bias (non-zero clamp refused), colour write mask, min/max blending;
- comparison and LOD-clamp samplers;
- occlusion queries;
- uniform bytes.

**Behind an extension:**
- depth clamp;
- dual-source blending;
- timestamps;
- the BC, ETC2 and ASTC compression families.

**`TODO(webgl)`:**
- compute and indirect dispatch;
- storage textures and storage in render stages (both need ES 3.1);
- indirect draws;
- cube arrays (ES 3.2);
- border colour;
- pipeline statistics;
- gpu-timestamps, which is not wired yet.

## Decisions settled in the contract

- **The BC family.** `textureCompressionBC` means every BC format the enum
  names, as WebGPU's `texture-compression-bc` does: BC1, BC3, BC5 and BC7,
  with their sRGB variants. On WebGL2 that takes S3TC, S3TC-sRGB, RGTC and
  BPTC together. A context that has only part of the family reports its
  formats one by one through `textureFormatSupport`. The conformance table
  checks every format in the family.
- **Refusals with no feature of their own:**
  - `TextureDimension.d1`;
  - a non-zero `DepthBias.clamp`.

  Each is refused with a plain `UnsupportedError` that names it, and each can
  become a feature later without breaking anything. The 19 extended formats
  are refused the same way on Impeller.
- **Buffer usages.** A usage is a promise from the caller. A backend checks it
  where its API would otherwise fail late, and refuses with an
  `ArgumentError`. A backend may also refuse `index` combined with `vertex` or
  `uniform`, because WebGL2 binds an element-array buffer for its whole life.
- **Bundles.** Inside a bundle, a `bind…` call answers from the stage's
  declarations at recording time. Native bundles and record-and-replay are
  both valid implementations.
- **Write mappings.** The bytes a `MapMode.write` mapping starts with are
  undefined. A staged mapping hands back zeros.
- **Bundles and indirect counts.** `multiDrawIndirect` with a count buffer may
  be refused inside a bundle with a `StateError`, because WebGPU bundles have
  no indirect count.
- **`indirectFirstInstance`.** It cannot be checked when the call is made,
  because the arguments live on the GPU. A non-zero first instance on a device
  without the feature is undefined.
- **`DepthTarget.face`.** It was added, so `layer` and `face` count the same
  way as on `ColorTarget`. A cube-array plane is `layer × 6 + face`.
  `TextureHandle.depthOrArrayLayers` is 6 for a cube on every backend.
- **Copy aspects.** A copy names no aspect, so a combined depth-stencil texture
  is refused for buffer copies.
- **Storage declarations.** `StageBindings` carries no storage declarations in
  1.0.
- **Depth bias.** The biased depth is what is tested and written. Whether a
  stage sees the bias in its own fragment depth is not promised.
